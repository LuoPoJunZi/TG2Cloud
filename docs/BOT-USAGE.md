# Telegram Bot 使用与命令

适用于当前 Linux 版的共享 Bot 核心，CloudDrive2 和 OpenList 操作相同；页面中的网关名称按实际 Edition 显示。安装入口见 [VPS 指南](VPS-INSTALL.md)和[内网指南](LAN-INSTALL.md)，首次挂载与验收见[存储网关配置](STORAGE.md)。

## 提交与处理流程

v1.3.3 增加[家庭成员授权](FAMILY-SHARING.md)：安装仍只填写一个管理员 ID；安装后在 `tg2cloud` 管理家人，成员仅操作自己的任务，共用保存目录。以下原管理员用法保留；v1.3.2 及更旧版本需升级 Bot 和管理工具后再使用。

仅支持配置的 Telegram 数字 ID 与 Bot 的一对一私聊；群组、频道直接发给 Bot 的消息不会创建任务。可以把有权保存的文件从来源聊天转发到自己的 Bot，但不自动监听频道、抓取历史或绕过内容保护。

1. 直接发送或转发视频、图片、文档等附件。
2. Bot 回复任务编号和最终文件名，表示任务已经持久化；不要因排队而反复转发。
3. 普通文件先下载到 Linux 暂存目录，再上传；单文件超过任务预算时自动采用流式传输。
4. CloudDrive2 使用临时对象、改名和最终大小复验；OpenList 直接写入预留的正式路径，不强行执行 MOVE。
5. 远端复验结果先入库，随后清理本地副本；完成后界面显示“Bot 完成”。重要文件还需到云存储官方客户端核对。

流式模式没有完整本地副本，中断后通常从头重传，不是字节级断点续传。文件名直接位于所选 WebDAV 目录，不自动增加年月子目录。命名过滤、媒体组共用说明及没有说明的限制见[恢复指南中的视频标题说明](RECOVERY.md)。

v1.3.3 命名增强支持从多语言说明中评分选标题，补识别混合随机 ID，过滤域名／推广与画质行；有意义原名、无说明兜底、非视频用法和已登记任务保持原规则。具体示例与限制见[多语言命名说明](RECOVERY.md#多语言候选评分与随机名称增强)。

## 命令速查

`123`、页码和文件名均是示例；命令在自己的 Bot 私聊中发送，而不是在 Linux 终端执行。

| 命令 | 用途与边界 |
| --- | --- |
| `/start`、`/status`、`/performance` | 打开当前状态首页。 |
| `/help` | 查看简短帮助。 |
| `/queue [页码]` | 每页 5 项最近任务，默认第 1 页，如 `/queue 2`。 |
| `/task 123` | 查看任务状态、失败原因、本地保留情况与验证记录。 |
| `/watch 123` | 约每 5 秒更新同一条进度消息；任务结束后停止，Bot 重启后需重新订阅。 |
| `/search 文件名` | 查找自己的任务；一次显示最多 5 项，更多结果需缩小关键词范围。 |
| `/tasks 状态 [最后编号]` | 按状态分页，例如 `/tasks failed`、`/tasks cancelled`；按回复中的下一页命令继续。 |
| `/pause`、`/resume` | 暂停／恢复新任务调度；活动传输继续，暂停状态在重启后保留，恢复不绕过资源或目的端保护。 |
| `/doctor` | 查看只读诊断、资源采样、目的端探测及并发窗口；不创建远端测试文件。 |
| `/retry 123` | 重排可恢复的失败任务；已取消或远端待核对任务改为提供确认流程，不直接重传。 |
| `/retry all` | 一次检查最多 100 个失败任务，跳过取消清理中及需要核对的任务；不是无限重试开关。 |
| `/restart 123` | 对已取消任务请求确认后重新转存。 |
| `/recover 123` | 对远端冲突任务请求确认后换名重传，保留原远端文件。 |
| `/stream 123` | 将符合条件且尚无本地副本的排队／下载失败任务切换为流式；不能强改活动任务。 |
| `/cancel 123` | 请求取消，可能删除本任务已经写入的远端对象；未能确认清理时保留本地副本，不冒充取消成功。 |
| `/orphans` | 只读扫描受管临时对象。 |
| `/orphans clean` | 获取一次性确认码后，按回复中的完整命令显式清理；不是清空目标目录。 |

恢复确认、远端冲突保护、扫描范围和删除上限统一见[任务恢复指南](RECOVERY.md)。不要把“取消”当成单纯暂停；保留活动传输时应使用 `/pause` 控制后续调度。

## 状态首页与资源页

`/start`、`/status` 和 `/performance` 使用同一首页。以下仅为显示示例，实际状态、网关和时间来自运行实例：

```text
☁️ TG2Cloud
🟢 正常运行 · OpenList

📋 任务
⏳ 2　⬇️ 1　⬆️ 0　❌ 0

📊 实时状态
⬇️ 8.25 MB/s
⬆️ 3.60 MB/s
🌐 11.85 MB/s

🕐 更新于 21:35:08
```

- `⏳` 是排队数，`⬇️` 是活动下载数，`⬆️` 是活动上传数（含流式），四项为零时仍显示。
- `❌` 的样式不变，统计与周切换规则见[首页失败计数](RECOVERY.md#首页失败计数)；清零不删除历史任务。
- 下载、上传速度来自各传输阶段；流式同时计入两个方向。`🌐` 是主机网络采样，不保证等于 Bot 两项速度之和。
- `🕐` 是页面生成时间，不代表最近一次真实 WebDAV 探测时间；探测和冷却信息看 `/doctor`。

首页下方 `📋` 打开最近任务，`🖥` 打开 VPS 资源，`🔄` 原地刷新。资源页单独显示 CPU、可用内存、可用磁盘和 Bot 暂存额度；`↩️` 返回首页。按钮刷新编辑同一条消息，不重复发送状态消息。

v1.3.3 界面移除“文件系统（暂存／数据库／日志／配置）”容量清单，后台仍按实际文件系统采样和执行磁盘保护；触发保护时保留必要的暂停原因提示。

`/doctor` 的“并发窗口：下载 1，上传 1”表示允许同时放行的额度，不表示各有一个活动任务；空闲时窗口仍可保留 1。实际活动数量看首页。资源可观测范围与磁盘保护见[恢复指南](RECOVERY.md#磁盘保护与诊断)。

## 任务状态怎么理解

| 状态阶段 | 含义 |
| --- | --- |
| 在排队／准备下载 | 已持久化，等待调度与资源条件。 |
| 下载中／等待上传 | 普通模式正在暂存，或已有完整本地文件等待上传。 |
| 上传中／流式传输 | 正在向 WebDAV 写入，不是云盘官方后台的入库进度。 |
| 校验／生成正式文件名 | 执行对应后端的提交及大小复验；OpenList 不要求 MOVE。 |
| 已接收，正在清理本地文件 | 远端大小复验已通过，本地清理尚未完成。 |
| Bot 完成 | Bot 流程结束；不是内容哈希一致或云盘官方最终完成的承诺。历史 `confirmed` 状态在日常界面并入这一项。 |
| 失败／需要核对 | 用 `/task 123` 看错误类型和安全恢复操作，不反复盲目重传。 |
| 已取消 | 已结束当前执行；重新转存需显式确认，历史记录保留。 |

新界面不要求逐个手工确认文件。验证等级、本地清理顺序和旧任务兼容说明见[验证等级与本地清理](RECOVERY.md#验证等级与本地清理)。

## Telegram 原生命令菜单

启动时注册的菜单只有 7 项，带参数的其他命令仍可手动输入：

```text
/status   查看系统状态
/queue    查看最近任务
/pause    暂停任务调度
/resume   恢复任务调度
/doctor   运行系统诊断
/orphans  检查临时文件
/help     查看使用帮助
```

菜单注册失败不阻止 Bot 启动，先直接发送 `/help`，再查看脱敏日志。升级前的旧按钮消息仅保留兼容，不代表当前首页增加了操作；请发送 `/status` 获取新首页。任务操作仍检查使用者和任务归属，危险清理及恢复继续使用现有确认机制。
