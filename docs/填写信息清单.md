# 一键部署前填写信息清单

适用于当前 Linux 公网 VPS 和可信内网安装。不要把真实秘密写进这份 Markdown；在自己连接目标主机的私有终端中按向导隐藏输入。

## 主机与资源

| 使用强度 | CPU | 内存 | 硬盘 | 说明 |
| --- | ---: | ---: | ---: | --- |
| 个人基础使用 | 2 核 | 4GB | 50GB SSD | 推荐起点，不是按容量单项判断的硬门槛 |
| 大量或长期批量传输 | 4 核 | 8GB | 80～100GB SSD | 为并发、网关缓存和失败保留留出余量 |

- [ ] Debian / Ubuntu 原生 64 位 AMD64／ARM64 用户态，Python 3.10+、Bash、curl、系统 CA 证书、时区数据库及交互终端。正式 v1.4.1 的双架构支持、NAT 预检、镜像证据与待执行的 Oracle 验收见[双架构说明](ARCHITECTURES.md)，NAS 额外限制见[内网指南](LAN-INSTALL.md)。
- [ ] 在目标 Linux 上以 root 执行；SSH 只是登录方式，脚本不会收集远端 SSH 密码或私钥。
- [ ] 选择 CloudDrive2 时必须有 `/dev/fuse`；OpenList 不因共用脚本而被要求具备 FUSE。
- [ ] 能访问 GitHub、Telegram、Docker 镜像仓库和目标云存储；内网模式同样需要外网下载能力。
- [ ] 安装盘与 Docker 数据盘均有足够可用空间和 inode；不同文件系统不能只看其中一个。
- [ ] 若通过 SSH 使用脚本，已自行核对服务器身份，并有浏览器访问管理页。

资源预检按 Edition 区分：CloudDrive2 至少约 1800MB 内存，OpenList 至少约 900MB；通过内存检查仍不代表磁盘、网络或传输条件合格。推荐磁盘不是专用分区要求，最终以实时探测及执行前复检为准。

带宽建议 100Mbps 或以上，按预期下载与上传量准备月流量；服务商是否同时统计两个方向，以实际计费规则为准。网关自己的缓存不受 Bot 任务预算直接控制。

## 公网还是可信内网

| 场景 | 需要准备 | 完整步骤 |
| --- | --- | --- |
| 公网 VPS | 所选 Edition 的独立管理域名、正确指向本机的 A/AAAA、TCP 80/443 放行；首次签发时 Cloudflare 使用“仅 DNS” | [VPS 安装与升级](VPS-INSTALL.md) |
| 可信内网 / NAS | 运行脚本的 Linux 或虚拟机自己的私有 IPv4、浏览器可达的可信网络；不需要公网域名 | [内网安装与边界](LAN-INSTALL.md) |

内网不等于任意 NAS 原生系统均兼容，也不等于离线或公网 HTTPS 的替代方案。两个公网 Edition 共用代理但使用不同域名；内网不应配置公网端口转发。

## Telegram

- [ ] 从 `@BotFather` 获取 Bot Token。
- [ ] 准备 Telegram API ID 和 API Hash。
- [ ] 准备唯一初始管理员的 Telegram 数字 ID，不是用户名；安装时不填多个 ID，家人之后用[用户管理](FAMILY-SHARING.md)授权。
- [ ] 确认同一个 Token 没有在另一实例同时运行；两个 Edition 各用自己的 Token。

安装后只在与 Bot 的私聊提交文件。命令和状态说明见[Bot 使用指南](BOT-USAGE.md)。

## 存储网关

- [ ] 选择 CloudDrive2 或 OpenList，目标云存储的账号由本人在该网关管理页登录／授权。
- [ ] 目标云存储剩余空间足够，挂载后能浏览预期目录；115 仅为示例。
- [ ] 准备 TG2Cloud 专用 WebDAV 用户，建议 `tg2cloud`；密码在向导中隐藏填写，也可留空安全生成。
- [ ] 在网关中创建同名、同密码的用户，具备当前后端需要的实际读写／删除等能力。
- [ ] 明确用户根目录与可选相对子目录，不在两处重复填写目标路径。
- [ ] OpenList 新装时私密保存初始化管理员密码；已有实例不自动重置。
- [ ] 挂载和用户配置完成后，再确认执行 WebDAV 写入验收，并核对 `TG2CLOUD_DESTINATION=OK`。

两版地址、权限差异、路径示例及验收含义统一见[存储网关配置](STORAGE.md)，不在此重复教程。云盘登录密码、Cookie、OAuth、二维码只交给你自己的网关，不交给 TG2Cloud 维护者。

## 磁盘预算与默认值

| 项目 | 默认／选择方式 |
| --- | --- |
| CloudDrive2 安装目录 | `/opt/tg2cloud-clouddrive2` |
| OpenList 安装目录 | `/opt/tg2cloud-openlist` |
| 本地任务预算 | 手动方案默认 `20GB`，不是磁盘分区 |
| 磁盘最少保留 | 默认 `8GB`，手动配置仍必须通过预检 |
| 时区 | 新装默认 `Asia/Shanghai`，不再询问；升级保留原值 |

首次交互安装会按当前资源给出流式优先、均衡和手动方案，由用户明确选择；已有实例升级保留原值，不静默应用新建议。单文件超过任务预算可走流式，不必把预算放大到文件大小。恢复与容量保护见[恢复指南](RECOVERY.md)。

脚本不自动分区、格式化、扩容或迁移 Docker 数据。历史备份和网关缓存也会消耗真实磁盘；查看与显式清理备份见[运维指南](OPERATIONS.md)。

## 已有实例升级前

- [ ] 先用所选 VPS／LAN 入口的 `--check` 核对身份、版本和计划；预检不执行升级。
- [ ] 已准备独立、私密的必要备份；升级回退点不等于完整灾难备份，范围见[恢复指南](RECOVERY.md)。
- [ ] 不删除数据库、Session 或版本文件来绕过官方基线检查，不并发从多个终端操作同一实例。
- [ ] 不先卸载、不重新填写 Token；原配置默认保留，实际升级后再验收转存。

## 明确不需要提供

- Telegram 私人账号密码、验证码或二次验证密码；
- 网盘密码、Cookie、OAuth Token、CloudDrive2 会员登录密码；
- 向维护者提供的 SSH 密码、私钥、完整配置、数据库或 Session；
- GitHub 账号密码或 Cloudflare API Token。

安全边界见[安全政策](../.github/SECURITY.md)。日志和截图仍可能包含私人文件名，发布前必须人工核对。

## 如果还要给家人看电影

- [ ] Bot 转存授权和手机读取授权分别规划，不把 Telegram 数字 ID 当作 WebDAV 账号。
- [ ] 准备与管理域名不同的外部域名，以及网关支持的独立原生只读用户能力。
- [ ] 核对真实共同目录；外部用户根目录直接限定到该目录，不暴露整个网关根目录。
- [ ] 每位家人使用自己的外部只读用户名／密码，停用时两套授权分别处理。

这是可选附加功能，主安装不会收集以上 WebDAV 外部域名和家庭账号。完成基础安装后另看[外部 WebDAV](external-webdav.md)；所有配置字段及实际运行数据位置见[配置参考](CONFIGURATION.md)。
