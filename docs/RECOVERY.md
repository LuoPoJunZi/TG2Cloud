# 任务恢复、验证与离线备份

本页恢复能力自 **v1.2.1** 提供，**v1.3.0** 继续保留；v1.2.0 EXE 不含这些改动。下载入口或重启旧容器不会自动升级 Bot；v1.3.0 起使用匹配的 Linux 脚本维护，旧 Windows EXE 停留在 v1.2.1。正式上线前应先在专用环境完成[维护版本验收](development/RELIABILITY-ACCEPTANCE.md)。

## 取消后重新转存

重新转发同一个已取消文件，或发送 `/restart 123`，Bot 会要求确认“重新转存”。确认有效期为 5 分钟，重启或任务状态变化后需要重新确认。活动任务继续去重，已完成任务继续沿用原去重规则。

恢复沿用原任务编号，保留状态与恢复记录；完整本地副本优先复用，没有完整副本则重新从 Telegram 获取。不删除历史任务，不创建第二个并发活动任务。连续点击确认只会有一次生效；取消尚未完成时不能恢复。

## 上传中断或远端冲突

先用 `/task 123` 查看失败原因、本地副本、验证等级与时间。普通模式会尽量保留完整本地文件，流式模式没有完整本地副本。

| 情况 | 操作 |
| --- | --- |
| 网络错误、5xx | 有限重试；仍失败时排查后使用 `/retry 123`。 |
| 401 / 403 | 自动重试停止；修正运行配置中的凭据或权限后再手动重试。 |
| 429 | 自动重试停止；等待网关/上游解除限制，勿连续点击。只读健康探测的冷却是独立机制。 |
| 记录路径有不完整文件、大小不一致、MOVE 结果不确定 | 保留本地和远端，暂停自动恢复；核对后使用 `/recover 123` 并确认换名重传。 |
| 本地文件缺失 | 检查挂载、磁盘与源消息；不能把缺失文件冒充可续传的完整副本。 |

换名重传会重新选择不冲突的路径，保留旧路径的保护记录；即使旧路径不再出现在新任务当前字段中，也不会因此被 `/orphans clean` 自动清除。它不是覆盖或删除确认。核对完旧文件后如需删除，应由用户在网关/云盘中独立决定。冲突任务不显示无效取消按钮，文字取消也不会清除这些不确定文件。

CloudDrive2 继续使用临时文件上传、改名及大小复验；OpenList 继续直接写预留的最终路径，不强行采用曾导致真实后端错误的 MOVE。OpenList 上传命令内部不反复重写最终路径，失败后交回任务层核对结果。

新路径选择只能防止本实例已知的冲突，不能代替存储端的原子“不覆盖”接口。不要让多个 Bot 或外部应用同时写入相同目标文件名；同一 Token 也不应同时启动两套实例。

## 验证等级与本地清理

新完成任务记录 `verification_method=size` 和验证时间：含义是**WebDAV 远端大小已验证**，不是内容哈希一致、也不是云盘官方后台完成。文件进入清理阶段前先持久化验证结果，随后才删除本地副本。重启后继续清理时重新检查远端；大小变化则撤销当前验证标记并转为待核对。

旧记录没有验证字段时显示“尚无验证记录”，不会被改写为失败或冒充做过验证。当前没有自动远端回读/哈希验证，避免增加不可控流量和对不可靠后端作出错误承诺。重要文件仍需在官方客户端核对大小、可打开性，必要时自行比对哈希。

## 首页失败计数

首页 `❌ 数字` 的样式不变，但 v1.2.1 只统计本地日历周内曾进入失败状态、当前仍失败的任务，每个任务计一次。按 Bot 容器现有 `TZ` 时区，每周一 00:00 切换统计范围；不是滚动七天，也不是删除任务。周初没有新失败即显示 0，刷新状态时生效；重启不会清空本周记录。恢复成功或离开失败状态后不再计入，历史失败仍可通过 `/tasks failed` 查看。

## 视频标题提取（v1.2.1）

仅对新收到的视频生效：有意义的原文件名保持不变；纯数字、默认 video/VID 编号或长十六进制 ID 名称，尝试从同一条消息说明中选取首个可用标题行。保留集数、年份及软件版本，使用原视频扩展名；不改已登记任务或已经保存到网盘的文件。

会过滤明文网址、无协议域名、Telegram 隐藏链接、`#话题`、`@用户名`、邮箱、广告/引流行、提取码/密码和常见大小/清晰度元数据；清除表情、不可见控制字符及非法文件名字符，并限制 UTF-8 名称长度。原名称保留在任务记录，发生改名时可在 `/task 编号` 详情查看。

这是保守的文本规则，不是视频内容识别；不访问链接、不读取评论区、不调用第三方 AI。没有可靠标题时沿用原名称，不编造主题。广告和标题写法无法穷尽，接收提示中的最终名称仍需用户核对；现有目标路径防冲突规则继续生效。

### 整组图片与视频共用标题

一次转发同一媒体组的图片、视频和说明时，Bot 从实际收到的本组说明中按消息顺序选择首个可用标题，统一生成 `标题-视频01.mp4`、`标题-图片01.jpg` 等名称。图片和视频各自编号，扩展名来自附件；本组中新任务原本有意义的名称也会替换，但原名保留。普通文档不套用图片/视频命名。

不会把前后两条无关消息或不同组的说明拼到一起。Telegram 分批投递时短暂等待媒体组；如果只收到一个成员，约 2 秒后按单条规则接收，不永久等待。说明严重迟到时，已经登记的任务不再改名；请核对接收提示。重复更新不新增任务，重复转发仍遵守去重。

只单独转发视频且没有说明时，Bot 无法补出它没收到的文字。可转发完整媒体组，或自行给视频添加说明/修改名称后发送。单独补发一条文字不会自动关联之前的视频，当前没有“回复视频填写标题”的交互。不会回查频道或获取评论区资源。

### main 待发布：长说明与引用块优先

主分支增强把“频道宣传＋联系方式”的视频原名也视为可替换名称。若本条消息有可靠说明，优先使用明确标题或较完整的引用块／长描述，同段的手工换行合并；链接、隐藏链接标签、`#话题`、`@联系方式`、推广行和凭据仍被过滤。正常有意义的单视频原名继续保留。

整组转发时，从本组可见说明中选取更完整的描述，继续按图片／视频编号。原名留在记录；已接收任务、已完成文件和远端路径不追溯改名。没有说明时保留原名称，不编造主题。这些改动尚未进入 v1.3.0 Release，一键入口只安装稳定版，不会因为 main 已更新就自动获得增强。

## 查询命令与扫描范围

- `/search 文件名`：按当前授权用户查询，通配符按普通文字处理，单次最多显示 5 项；更多结果请缩小范围。
- `/tasks failed`、`/tasks cancelled`：按状态查询，`failed` 包含全部失败状态；依提示用最后编号继续翻页。
- `/task 123`：按编号查看详情；文字命令和按钮均检查权限和任务归属。
- `/orphans`：只扫描配置目标目录**第一层**的受管 `.uploading-*` 文件；不是递归扫网盘。

遗留扫描增量读取清单，不再静默截取前 10,000 项。结果分别报告已检查条目和已发现临时对象。仍有约 40 秒读取超时、100 万条目、2 万候选和单条 1 MiB 的资源边界；达到限制、超时、清单损坏或进程失败都显示“未完成”，禁止生成/执行清理计划。完整表示本次清单完整，并不表示远端在扫描期间完全没有变化。

删除保护保持独立：最多 100 项、一次性确认、到期失效、执行前重新扫描并检查任务引用、范围外路径拒绝。扫描量增加不会扩大删除权限。

## 磁盘保护与诊断

20 GB 是 Bot 任务预算，8 GB 是默认保留空间，均沿用原配置。运行时按文件系统分组显示暂存、数据库、日志与配置目录，不将同一盘的剩余容量重复相加。新下载预留同时考虑实时可用空间和其他任务尚未写入的预留量。观测到相关文件系统触及安全线时拒绝新文件并暂停新下载；空间恢复后重新采样、恢复调度，用户主动 `/pause` 不会被自动解除。

这不是整机存储管理：Bot 无法读取未挂载进容器的独立 Docker/网关缓存盘，也不会自动删除缓存、日志或历史备份。运行中的上传可能继续占用网关盘，不能保证阻止外部程序耗尽该盘。先用部署器资源检测和宿主机只读 `df -h`、`df -i`、`docker system df` 排查，保留失败任务后再决定如何释放空间。

## 备份范围必须区分

| 备份 | 覆盖 | 不应假设包含 |
| --- | --- | --- |
| CloudDrive2 升级回退点 | 程序、配置、可用时的独立业务 DB 快照 | Telegram Session、完整网关授权状态、下载、HTTPS |
| OpenList 业务备份 | 程序配置、业务 DB 快照、OpenList 状态 | Telegram Session、下载、HTTPS |
| 共享代理备份 | 两版路由、Nginx/Compose、完整证书与 ACME 账户、续期记录 | 业务 DB、Session、网关授权、下载 |
| 新离线快照包 | `.env`、Compose、`data/tg115.db`、`data/bot.session`、`config/`、所选网关配置 | 下载、日志、共享 HTTPS、云端实际文件 |

本轮没有替换已有备份按钮或加一键生产恢复。OpenList 上次已合入的快照验证、digest 镜像回退和有限停机保护继续保留；CloudDrive2 补齐同类 DB 校验、同目录暂存验证后替换、停止 Bot 失败则中止的保护。

### 可选离线快照工具

仅适用于标准布局，运行 Python 3.12+。先安排维护窗口，停止会写入所选数据库、Session 和网关状态的服务；保护当前实例，再制作**独立、静止的副本**。SQLite 应正常关闭或通过备份接口生成一致快照，不能删除 WAL 来强行通过检查。不要把运行中的 `/opt/tg2cloud-*` 直接当成离线副本。外部网关、定制目录、链接或非 SQLite 状态需要单独备份方案。

在含 `app/` 的匹配源码目录执行，下面路径均是示例，版本填写快照对应的实际源码版本；不在源码仓库保存真实备份：

```bash
python3 -m app.backup_bundle pack /srv/private-backups/openlist.tar.gz --snapshot /srv/private-snapshots/openlist --edition openlist --version 1.2.1 --offline-confirmed
python3 -m app.backup_bundle check /srv/private-backups/openlist.tar.gz --scratch /srv/private-restore-check --edition openlist --version 1.2.1
```

CloudDrive2 将 Edition 改为 `clouddrive2`，离线副本需包含 `clouddrive/config/`。工具不启动/停止服务、不读取在线凭据、不覆盖现有归档或生产数据；首次创建的坏包会删除，原始副本不动。

包内记录版本、Edition、文件范围、大小与逐文件 SHA256；检查拒绝跨 Edition、降级、跨主版本、不完整清单、目录穿越、链接、重复成员、校验失败和不一致 DB。默认上限 2 GiB/20,000 文件，预留至少 256 MiB；超过限制应另行制定备份方案，不能关掉检查。归档 Unix 权限 600，隔离目录 700；Windows 上另需受限 ACL。清单不是数字签名，只使用自己可信来源的归档，并私密保存离机副本。

检查只在新建隔离目录解包，完成后清理该目录。**结构、哈希和数据库通过不等于服务能恢复运行**；没有在线覆盖 Restore 命令。恢复前另核对目标版本/镜像、挂载、容量、同名文件、授权及代理，先保存当前可用数据，再在隔离主机恢复，确保旧 Bot 已停止且同一 Token 不双开。

## 数据库兼容与回退

首次启动自动以事务添加可空的错误/验证字段、恢复历史及受保护路径表；保留 `tg115.db` 文件名、任务编号、状态名、去重索引及 Session，无手动改表或新环境变量。增加字段后旧记录仍可显示；迁移重复执行安全。

升级前保留独立校验过的 DB 和程序/镜像回退点。新增字段是兼容扩展，但**旧程序不理解远端保护记录**，不要简单换回旧镜像继续处理新版本任务。需要回退时先停止 Bot、另外保存当前完整数据，核对新版本产生的远端文件，然后在隔离环境验证升级前 DB 与匹配程序一起恢复；避免同一任务重复写入。自动部署回退点不等于长期灾难恢复备份。

## 容器安全边界

Bot 继续使用 UID 10001、只读根文件系统、`cap_drop: ALL` 和 `no-new-privileges`；OpenList 继续使用受限用户。没有扩大挂载、增加 Docker socket、凭据回传或遥测。

CloudDrive2 的 `privileged`、host PID、FUSE/传播挂载属于当前已验证的挂载方案，风险是能接触较多宿主资源；本轮不在缺少实机 FUSE 回归时直接移除。建议使用专用主机或虚拟机，不与不可信容器混用。HTTPS 共享代理的 host 网络用于现有管理入口，后端仍只绑定回环；此轮未改变 Compose 或管理端口。

传输错误按固定分类展示，运行日志还对已知凭据和 URL 做脱敏。但文件名、用户自定义消息等仍可能包含私人内容，导出日志/截图前仍需人工核对。
