## 1. 旧版本可信基线

`deployment/baselines.py` 随新 helper 携带受审阅的版本 → 原提交 → 两 Edition 载荷摘要目录。当前覆盖 **v1.3.4、v1.4.0、v1.4.1、v1.4.2**。摘要包含完整部署相对路径及各文件 SHA256，规范化历史 CRLF；不会执行旧 Python 来获取版本、清单或摘要。

公网／LAN 升级在取得最新正式目标后，对目录内的旧版本直接取得固定原提交、验证两 Edition 载荷，再沿用原有实例逐文件检查、运行身份、锁、候选、快照与回退流程。不依赖旧 Release／Tag 仍存在，不接受任意 SHA，也不相信一个自行填写的版本记录就放行。缺失／额外／修改源码仍停止；未知旧版仍要求公开正式 Release，下载失败不退回 main。

HTTP 404、403、429 与网络／TLS／超时分别提示，不显示远端响应正文或访问凭据。目录是随可信发布代码分发的兼容数据，不是数字签名。历史目录不能保证 GitHub 网络永久可用，也不扩大可自动升级的网关镜像范围。

维护者从**已经单独核实为原正式版**的本地 Git 提交生成待审阅条目：

```bash
python3 -B .github/scripts/baseline_metadata.py --tag v1.3.4 --commit ef35d133a9e25572ff5f8363819d5c8e8984e74c
```

工具只输出候选元数据，不自动信任新提交、不改目录、不创建发布。自动回归以完整 Git 历史重生成现有条目；历史验收保持[原记录](V142-ACCEPTANCE.md)，不回写成当时自动升级已经通过。

## 2. 实例快照／导出

新管理工具 `tg2cloud` → **7. 备份管理**：

| 选项 | 行为 |
| --- | --- |
| 6. 创建实例快照／导出 | 明确确认维护窗口后，检查无活动传输，停止所选 Bot／网关，复制限定配置并制作验证过的归档，然后恢复原来运行的容器 |
| 7. 实例快照隔离预检 | 对用户指定的私密归档执行现有结构、SHA256 和数据库检查，只在新临时目录解包，不覆盖生产资料或启动 Bot |

默认私密目录 `/opt/tg2cloud-snapshots/<edition>`，与卸载默认清理范围分离；用户应再保存私密离机副本。路径必须绝对、归属／权限可核验、没有链接，不能放进实例或其他 TG2Cloud 运行目录。活动任务、硬链接、特殊文件、嵌套挂载、自定义 DATA_DIR、覆盖不完整、空间不足或未完成操作记录均停止。

归档包含 `.env`、Compose、业务 SQLite、Telegram Session、`config/`、所选网关配置目录，以及存在时的原发布身份记录。SQLite 使用现有一致性备份接口。默认上限沿用 2 GiB／20,000 文件；不递归打包 CloudDrive2 FUSE／云端数据，不靠放宽上限假装完整。

**不包含** downloads、日志、共享 HTTPS、LAN／外部 WebDAV 独立状态、程序镜像或云端文件；有失败保留文件时须另行保存 downloads。共享代理继续单独备份。网关的内部／外部数据库、插件及其他部署若不在上述受管目录，不在覆盖承诺中；快照结构有效不保证所有网关授权可以恢复。

只按已核验的原容器 ID 停启；原先停止的 Bot 不会被启动。网关先恢复，再恢复 Bot；这里只确认运行状态，业务就绪须另查。异常及普通中断尝试恢复原状态，恢复失败保留归档与私密操作日志，阻止下一次快照，不误称已经回退。断电／SIGKILL 后不会自动重放日志，须先人工核对；不提供一键覆盖生产 Restore。

备份会短暂中断所选网关的管理页与外部 WebDAV 读取，不停止另一 Edition 或共享代理。CLI 持有所选 Edition 锁并在锁内复核身份；不要与手工 Docker 操作同时执行。

## 3. 业务就绪检查

`tg2cloud` → **11. 业务就绪检查**，与现有容器心跳健康检查分离：

```text
运行心跳：通过
Telegram 连接：通过
WebDAV 最近目录探测：通过
调度开关：通过
新下载空间：通过
业务就绪：基础条件通过；使用最近观察，不额外请求 Telegram/WebDAV，不代表可写或实际转存完成。
```

运行 Bot 在资源采样后原子写入小型观察文件，只含布尔／枚举、计数、版本、时间与冷却信息，不含账号、文件名、路径、Token、原错误正文或 Session。检查不新建 Telegram 会话、不绕过 OpenList 401／429 冷却、不发测试写入、不重启容器。

原名为 healthy 的容器仍只按现有心跳判断，不因网络波动新增自动重启。观察文件缺失、过期、早于本进程、协议未知或版本不匹配时显示未核实；旧 Bot 不支持时明确提示升级对应运行代码，不能把更新离线工具当作 Bot 已更新。只读账号根目录可达但目标目录缺失会显示“仅账号根目录可读”；连接检查不是逐次重新验证 Telegram 授权。

## 4. Nginx 生命周期回归与实机门槛

在现有离线事务回归中增加“删除最后管理路由仍保留外部 DAV 及续期域名”。扩展原生 CI 已启用的 `test_external_nginx_docker.py`，使用随机隔离网络、测试容器、合成账号／证书，不绑定宿主端口：

- 目录挂载内原子替换认证文件后，新密码生效、旧密码失效；原 Bot／管理员账号不能通过入口。
- 外部 DAV disable／enable、删除管理路由、测试代理重启与删除附加站点，均保留原测试网站。
- 合成证书更换并 reload 后，TLS 实际提供新证书摘要，外部代理 ID 与原网站保持不变。
- 网关重建时占住原 IP，验证稳定别名／Docker DNS 能重新解析新 IP，无须重启外部代理。

本地 Windows 没有 Docker daemon，以上真实 Nginx 集成未运行，不能写成通过；离线替身也不代表实机 ACME。仅在**专用本地 Linux 测试 daemon**运行：

```bash
TG2CLOUD_TEST_EXTERNAL_NGINX_DOCKER=1 PYTHONPATH=src python3 -B -m unittest discover -s tests -p test_external_nginx_docker.py -v
```

后续仍须单独授权真实测试域名／VPS，验收 DNS、ACME staging、实际续期 dry-run、已有网站业务、外部代理重建后的身份复核及故障回切。不要把测试代理重启等同生产代理无中断迁移；本轮没有连接此前 VPS。

## 5. 命名预览与样例回归

新工具独立命令 `tg2cloud naming-preview`，或管理菜单 **12. 命名预览（不转存）**。本地源码可从任意工作目录调用：

```bash
python3 -B /path/to/TG2Cloud/scripts/run_source.py naming-preview --help
python3 -B /path/to/TG2Cloud/scripts/run_source.py naming-preview --input /path/to/TG2Cloud/tests/fixtures/naming-preview.json --json
```

样例 JSON 字段为 `file_name`、`caption`、`media_extension`，可选 `fallback`；最多 64 KiB，说明最多 8192 字符。不要把真实说明、网址令牌或秘密写入命令行参数。交互模式按行粘贴说明，单独一行 `.` 结束。

预览与转存共用 `explain_media_name()` 的同一选择路径，原 `media_file_name()` 返回值保持兼容；显示候选最终文件名、选择原因及原规则评分，评分不是 AI 置信度。不下载、不上传、不查数据库、不检查远端重名、不改历史任务或云端文件。

这是**单媒体文字模拟**，没有收到 Telegram 实体时不能推断隐藏链接、评论或媒体组关联；相册统一命名仍由原事件流程处理。没有可靠标题继续原回退，不因预览功能提高改名激进程度。公开样例使用合成多语言文字，实际用户样例须先脱敏。
