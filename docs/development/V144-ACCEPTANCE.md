这是两次真实执行的升级，不是 `--check` 或只更新管理工具。开始时向导和新菜单已是 v1.4.4，但运行中的 Bot 仍显示 v1.4.3；只有后续代码／版本检查、健康状态、成功标记和结果摘要，才支持升级完成的结论。

宿主 Python 版本是这两份日志中的环境事实，不改变 Bot 镜像使用 Python 3.12，也不把 CLI 的 Python 3.10／3.13 双架构 CI 扩大为完整 Python 3.14 测试矩阵。两台主机各自在原生架构上升级，不是跨 CPU 迁移或 QEMU 验收。

## 日志分级与容量提醒

两份日志均展示 `[信息]` 阶段提示和最终结果摘要。Debian AMD64 主机还出现安装文件系统总容量低于推荐 50GB 的 `[提醒]`，随后解释推荐值不是硬性门槛，并在摘要中汇总“1 类常见提醒；本次未阻断基础步骤”。容量校验及后续升级均实际通过，才支持这个限定结论。

两次构建中的依赖安装层均命中 `CACHED`，没有重新输出旧 v1.4.3 日志中的 pip root、CA rehash 和固定 UID 三类构建提示；这不是新版把所有 WARNING 隐藏了，也不是本次重新实测这三种提示的分类。未知 WARNING、真正错误、失败／中断摘要仍需按[FAQ](../FAQ.md)及[运维说明](../OPERATIONS.md#安装日志与结果摘要v144)判断，不能推广为“所有警告均无影响”。
