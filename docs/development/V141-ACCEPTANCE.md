## APT 失败的实际原因

首次尝试停在宿主 apt-get update。活跃的 ubuntu.sources 中，安全更新源 URI 为 `https:///ubuntu-ports/`，缺少主机名；APT 日志将其显示成 `https:/ubuntu-ports`，因此按日志缩写做原样搜索没有匹配。

用户先备份该配置，再仅修正对应 URI 为 `https://ports.ubuntu.com/ubuntu-ports/`；随后 apt-get update 成功，重新执行原入口完成安装。未通过禁用安全源、降低签名检查或跳过更新绕过问题，不能归因于 ARM64 或 NAT 不受支持。

这是用户修复其系统配置，不是 TG2Cloud 新增自动换源功能。其他主机须核对自己的发行版、活跃源文件与签名配置，不能照搬整个源文件或批量替换发行代号。排查步骤见[常见问题](../FAQ.md#apt-报没有-release-文件怎么办)。

此前出现过提示交错、反复询问；后续进程快照没有残留 Python 向导，本次重跑也未复现。没有确认根因或修改交互代码，不能将“这次未复现”记为“已修复”。
