# 下一轮稳定性维护完善（待发布）

本页记录 v1.4.4 之后的本地开发工作，不修改正式版本、Tag、Release 或在线 helper pin。公开一键命令仍使用已经发布的代码；修改文档不会自动升级已有实例。

## 1. 诊断从状态汇总到处理建议

沿用 `tg2cloud` → **12. 故障诊断报告**，不增加主菜单。新代码复用已存在的只读入口检查，汇总 HTTPS／LAN 本机结果；共享状态不受支持、身份无法确认或探测失败时显示未核实或未通过，不执行签发、续期、reload 或服务重启。

报告先列容器和配置，再提示连接／账号权限、限流冷却、容量、远端冲突及入口的处理顺序。建议仅含固定文字，不带账号、域名、私人路径、文件名、原始错误或认证头。过去七天的当前失败任务分类不等于实时故障。

- 401：核对 Bot 专用账号，不以外部只读用户代替。
- 403：核对账号根目录、相对子目录及写入权限，不自动扩大权限。
- 429／冷却：等待现有退避，不追加写入探测或重启绕过。
- 远端冲突：保留本地与远端现场，按任务详情确认安全恢复，不自动覆盖或删除。
- 本机入口通过：不等于另一网络可访问、WebDAV 可写或真实转存已完成。

现有主菜单、Bot 状态 UI 与业务状态机不改变。

## 2. 隔离数据库恢复演练

原 `bundle check` 仍只检查归档、容量、文件摘要与数据库完整性。新增工具在这些检查全部通过后，使用当前可信源码的 `TaskDB` 打开临时数据库，运行既有迁移与重启恢复逻辑，再核对任务总数及数据库完整性。

在**完整源码 checkout** 中运行，不要求 Bot 依赖。参数中的私密目录、归档和 Edition 必须替换为自己的值：

```bash
PYTHONPATH=src python3 -B -m tg2cloud.persistence.rehearsal /srv/private-backups/instance.tar.gz --scratch /srv/private-restore-check --edition clouddrive2
```

OpenList 使用 `--edition openlist`。`--help` 查看参数，`--json` 输出脱敏汇总。工具不加入主菜单，不是正式 v1.4.4 的命令；新模块纳入共享 Bot 运行源码清单，但不要求旧离线管理包具备整个数据库实现。

1. 归档和隔离父目录必须无符号链接并满足私密权限，归档 `0600`、父目录 `0700`；只使用自己控制的可信快照。完整性校验不是来源签名。
2. 仅打开新临时目录中的副本，不执行归档内程序、Compose 或 `.env`，不加载 Session，不启动网关，不连接 Telegram／WebDAV。
3. 快照不含 downloads。演练仅在副本中清空本地路径引用，用空的隔离暂存目录模拟文件缺失；绝不按数据库里的原路径读取生产文件，不能据此判定真实本地文件已丢失。
4. 仅验证当前执行代码的能力，拒绝高于当前支持 schema 的数据库、非业务 SQLite 及超过 20,000 个任务的演练。原有 2 GiB／20,000 文件上限不放宽；任务数量上限与文件数量上限不同。
5. 正常结束、失败或普通中断清理自己创建的临时副本，原归档和实例不变。断电／SIGKILL 后若遗留私密临时目录，应人工核对再清理，不声称能捕获所有强制终止。
6. 成功只代表数据库启动／迁移及恢复逻辑通过，不代表网关能启动、Session 可登录、云盘授权可恢复、真实文件可读或生产切换成功。

复核时补强原预检：拒绝归档中超出已声明覆盖范围的文件以及 SQLite `-wal`／`-shm`／`-journal` 旁文件，避免把活动数据库片段当作静止快照；现有合法快照布局不变。数据库初始化失败或普通中断会关闭连接，再交由隔离目录清理，不修改迁移 schema。

正式恢复仍按[备份恢复指南](../BACKUP-RESTORE.md)安排，保留可用实例和匹配代码／数据库，不启动第二个同 Token 的 Bot。

## 3. 旧版升级与发布预检

基线目录补齐经历史发布记录和本地正式 Tag 核对的 v1.4.3、v1.4.4 原提交及两 Edition 摘要。即使旧 Release／Tag 以后移除，受支持旧版仍按固定提交下载和逐文件验证；缺失、修改、额外源码或未知版本继续停止，不接受用户任填 SHA。

维护者在完整 Git checkout 执行只读本地预检：

```bash
python3 -B .github/scripts/maintenance_preflight.py --previous-tag v1.4.4
```

检查版本资料、bootstrap／runtime 清单、所有已审阅旧版摘要，以及三个入口的固定 helper 与**工作树实际文件**是否一致。`--json` 提供机器可读结果；有待处理项退出码为 1。历史 Git 对象缺失会阻断，不联网兜底信任未知资料。

本轮 helper 尚未公开，预期 helper 一致性检查会报告“发布前待处理”。不能通过忽略 pin 或伪造提交消除这个门槛。发布仍需：审阅并选定新版本 → 公开辅助提交 A 并验证 → 入口 B 固定 A 的真实 SHA 和清单 → B 及正式同 Tag 的原生 AMD64／ARM64 CI → 核对源码资产与校验清单。

静态预检通过也不代表远端 CI、实机验收或 Release 完成；原源码发布工具的严格检查不降低。

自动测试使用临时 SQLite／归档、模拟 Docker／入口及现有传输替身。两后端补测“目的端已接收文件，Bot 重启后只复验，不再次上传”，不扩大为云盘官方最终完成承诺。
