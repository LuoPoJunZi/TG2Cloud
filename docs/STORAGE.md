# 存储网关配置与 WebDAV 验收

本文承接 Linux 安装向导之后的网关配置。公网安装、域名和证书见 [VPS 指南](VPS-INSTALL.md)，可信内网地址与 HTTP 风险见[内网指南](LAN-INSTALL.md)；不需要为配置云存储重新部署 Bot。

## 管理页和 Bot 地址不是一回事

| 用途 | CloudDrive2 | OpenList |
| --- | --- | --- |
| 浏览器管理页 | 公网使用自己的 HTTPS 域名；内网使用向导给出的地址 | 同左，使用 OpenList 对应域名或内网地址 |
| 同机受管 Bot 的 WebDAV 地址 | `http://tg2cloud-clouddrive2:19798/dav` | `http://tg2cloud-openlist:5244/dav/` |
| 标准安装目录 | `/opt/tg2cloud-clouddrive2` | `/opt/tg2cloud-openlist` |

后两项由受管部署配置；Linux 首次向导收集专用用户、密码和相对子目录，不要求填写公网 WebDAV URL。**不要把管理域名或内网浏览器地址替换进 Bot 配置**：管理入口只代理页面，公开的 `/dav`、`/dav/` 被阻断是预期安全行为。Bot 通过自己的 Docker 网络连接网关。

两个 Edition 可以共存，但应使用不同 Bot Token、独立实例配置及持久化数据。不要让两套运行实例同时处理同一个 Token，也不要让多个写入方同时写同一个目标文件名。

## CloudDrive2

1. 打开安装向导给出的管理页，由本人登录自己的 CloudDrive2。
2. 添加并授权目标云存储，确认可以浏览预期目录，且云存储剩余空间足够。115 是示例，不是唯一目标。
3. 在 CloudDrive2 中启用 WebDAV，创建 TG2Cloud 专用用户。
4. 用户名和密码必须与安装向导保存的值完全一致；不要使用 CloudDrive2 会员密码或网盘账号密码代替。
5. 选择该用户的 WebDAV 根目录，关闭只读，授予读取、写入、改名和删除所需能力，再执行写入验收。

网关账号、会员及具体存储的功能限制以你实际使用的 CloudDrive2 环境为准；TG2Cloud 不接收云盘 Cookie、OAuth Token 或登录二维码。这些信息只在你自己的网关中配置。

## OpenList

1. 通过 OpenList 对应管理地址登录。全新实例的初始化管理员密码由向导生成；显示方式见 [VPS 凭据说明](VPS-INSTALL.md#https-续做与验收)或[内网指南](LAN-INSTALL.md)。已有实例不自动重置管理员密码。
2. 在自己的 OpenList 后台添加并授权目标云存储（例如 115 Open），先确认挂载可以浏览。
3. 创建专用普通 WebDAV 用户，建议用户名 `tg2cloud`，并使用向导保存的同一密码。管理员登录密码与该 WebDAV 密码不是一回事。
4. 为用户设置基本路径，并授予目录列表、读取、创建／写入和删除能力；不同 OpenList 版本的权限名称可能不同，应以实际能力为准。
5. 执行写入验收。当前 OpenList Edition 直接写入预留的最终路径，不要求用 WebDAV MOVE 完成改名。

已有实例中的旧用户名与明确配置的子目录继续保留，升级不会静默改成 `tg2cloud`。向导显示的“初始化管理员密码”可能已被你在管理页更换，不能把保存的初始值当作当前密码；需要恢复时先参考 OpenList 自身的管理说明，不反复重新部署或自动改密。

## Bot 写入账号与外部只读账号

| 能力 | CloudDrive2 Bot 用户 | OpenList Bot 用户 | 外部 WebDAV 用户 |
| --- | --- | --- | --- |
| 列目录、读取、查询大小 | 需要 | 需要 | 需要 |
| 创建文件／写入 | 需要 | 需要 | 禁止 |
| 改名／MOVE | 正常提交流程需要 | 当前直接写最终路径，不依赖 MOVE | 禁止 |
| 删除 | 本任务清理与验收需要 | 本任务清理与验收需要 | 禁止 |
| 网关管理／任意目录访问 | 不应授予不必要权限 | 不使用管理员替代 | 禁止；根目录直接限定到确认目录 |

Bot 删除能力只用于受管对象和确认清理，不是随意清空网盘的权限承诺。网关的真实权限由自身配置实现，Nginx 方法限制不能替代原生只读。后台不支持独立用户／目录隔离时，外部附加功能应停止，不借用 Bot 账号。

家人提交文件仍共用一套 Bot 写入账号，读取电影则使用各自独立的只读账号；两种授权不联动，详见[家庭共享](FAMILY-SHARING.md)。

## 根目录与子目录只组合一次

最终位置是“WebDAV 用户可见根目录 + 向导填写的相对子目录 + 文件名”。以下为任意云存储的示例；替换为你实际挂载名称：

| 网关用户的根目录／基本路径 | 向导中的子目录 | 文件位置示例 |
| --- | --- | --- |
| `/MyCloud/Telegram` | 留空 | `/MyCloud/Telegram/文件名.mp4` |
| `/MyCloud` | `Telegram` | `/MyCloud/Telegram/文件名.mp4` |
| `/` | `MyCloud/Telegram` | `/MyCloud/Telegram/文件名.mp4` |

不要在两处重复填写完整路径，否则会产生多层同名目录。子目录使用相对路径及 `/`，不要填写 URL、`..` 或反斜杠。全新 OpenList 的默认子目录为空；无需为了使用 Bot 强行增加目录层级。

安装后要改 WebDAV 凭据或目标目录，先处理已有任务，再按[配置变更流程](OPERATIONS.md#修改运行配置)操作；重新运行升级向导默认保留现有值。

修改子目录不会移动已经保存的云端文件，也不会让旧任务自动重新上传。存在外部 WebDAV 时，应先核对其绑定；Bot 改路径后附加入口不会自动扩大到新目录，需显式 `configure` 并重新核对账号权限。

## 写入验收与成功标记

在网关里完成挂载和专用用户后，再按 VPS／LAN 指南显式执行 `--verify`。它仍会要求确认随机测试文件的创建和清理；不是只读检查。底层维护命令及其影响见[运维命令](OPERATIONS.md#实例管理命令)。

验收从 Bot 容器使用实际保存的配置执行：

| 阶段 | 实际操作 |
| --- | --- |
| 认证与目录 | 验证专用 WebDAV 用户，检查并准备目标目录。 |
| 写入 | 生成 256 字节随机文件并上传。 |
| 大小 | 核对远端文件大小。 |
| CloudDrive2 提交 | 临时文件改名，复验正式文件大小及临时路径消失。 |
| OpenList 提交 | 已直接写最终路径，输出 `TG2CLOUD_WEBDAV_MOVE=NOT_REQUIRED`，不是漏检或失败。 |
| 清理 | 删除远端测试文件并复查，同时清理本地测试文件。 |

最终成功标记是 `TG2CLOUD_DESTINATION=OK`。容器 `healthy`、只读目录可访问或 HTTPS 可打开，不能代替这个结果；测试中断或显示清理警告时，先核对脱敏日志，不手动批量删除不确定对象。认证和限流处理见[运维排查](OPERATIONS.md#openlist-限流诊断)，任务结果不确定时见[恢复指南](RECOVERY.md#上传中断或远端冲突)。

该结果证明当前 Bot 到 WebDAV 的所需操作和大小复验通过，不证明内容哈希一致或云盘官方已完成入库。批量使用前建议使用自己的测试文件依次验证：小文件、普通落盘、超过预算或手动切换的流式任务，以及传输中 Bot 重启后的恢复。只有愿意删除的测试任务才用于 `/cancel` 验收；不要拿已有云盘文件做删除实验。最后在云盘官方客户端检查文件大小与可打开性。这些是人工验收建议，不是声明本轮已经执行。

## 验收失败时按层排查

| 现象 | 检查顺序 |
| --- | --- |
| 401 | 网关中的专用用户名／密码与实例保存值是否一致，是否把管理员密码当成 WebDAV 密码。 |
| 403 | 用户根目录、列表／写入／删除权限，以及当前访问的是管理域名还是 Docker 内部地址。 |
| 404／找不到目录 | 挂载是否成功，根目录与相对子目录是否重复，路径是否属于该用户可见范围。 |
| 429 | 暂停反复验收，排查上游／网关限制；只读探测有独立退避，不能靠刷新绕过。 |
| 大小不一致／写后路径不确定 | 保留远端和本地信息，按任务恢复规则核对，不自动覆盖／批量删除。 |
| 容器地址解析失败 | 核对 Bot 与网关的受管网络和容器身份，不把 URL 改成公网域名。 |

具体冷却、任务恢复和脱敏方法见[运维](OPERATIONS.md#openlist-限流诊断)、[恢复](RECOVERY.md)与 [FAQ](FAQ.md)。
