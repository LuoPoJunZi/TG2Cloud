主菜单下通常只有一层功能子菜单；外部 WebDAV 可包含用户管理等独立子菜单，统一从主菜单进入，无需额外安装命令。选择操作对象、填写域名／路径／阈值以及安全确认仍是必要的执行步骤。HTTPS 修复需要选择代理模式时继续执行原授权检查，不为减少菜单层级绕过共享代理安全流程。

维护流程核验本机默认 Docker、实例身份、挂载、配置与实际代码指纹。启停、验收等写操作持有所选 Edition 锁并复核实例；代理操作继续使用共享事务锁。未知、残留、部分安装或改动后的实例不会被菜单接管。日志仍可能包含个人文件名，分享前人工复核。

离线代码在 `/opt/tg2cloud-cli/runtime/<摘要>/`，安装来源、版本及文件哈希在私密 `installation.json`，不包含实例 `.env`、数据库或 Session。运行前校验清单，未知版本、改动、缺失文件和未知命令不覆盖。摘要用于一致性检查，不是数字签名。状态／日志不更新自己，只有再次确认安装计划才安装相应向导代码；日常更新保留旧代码，最后完整卸载的清理规则见下文。退出、断电或失败不会被描述为完成回退。

只卸载 CloudDrive2 不删除／重启 OpenList 的 Bot、网关或数据；共享代理移除对应路由时可能短暂重载，另一 Edition 的域名继续保留。最后一套执行默认完整清理后，核对无剩余容器（包括已停止/部分实例）、网络、管理/附加路由、保留数据/备份或挂载依赖，才移除受管 `/usr/local/bin/tg2cloud` 与 `/opt/tg2cloud-cli` 全部已核验运行包；卸载后退出当前菜单，不再读取刚删除的代码。`--keep-data`、仅删数据但保留备份、有其他 Edition 或身份不明时保留工具。未知同名命令、未知文件、忙碌或清理失败会明确提示，不强删、不冒充完整清理。系统 Docker/Nginx、云端文件、镜像缓存及防并发锁元数据不清理，不能保证系统逐字节恢复原样。

若原来以 pip 安装了同名 `/usr/local/bin/tg2cloud`，向导会停止，请先人工核对命令归属，不自动覆盖或删除。显式 `tg2cloud install --help`、`lan --help` 等兼容分发仍可用。v1.4.7 起外部 WebDAV 菜单只整合操作入口，不加入主安装向导；账号、只读目录、HTTPS 路由及卸载生命周期继续独立，历史 `tg2cloud-webdav` 仍兼容。

### 安装日志与结果摘要（v1.4.4）

此项在现有 Linux 公网／内网安装执行层补充反馈，不改变上面已确认的菜单，不增加 Bot 命令或运行依赖。此项随 v1.4.4 源码提供，须升级匹配的离线工具后使用；v1.4.3 的历史资产不包含新增反馈。安装工具、Bot 与文档版本分别核对，不因文档更新就假定 VPS 已更新。

| 日志类别 | 含义与处理 |
| --- | --- |
| `[信息]` | TG2Cloud 正常阶段信息；APT、Docker 等原始进度仍保留。 |
| `[提醒]` | 在受管基础安装、带 BuildKit 阶段标记的构建输出中识别到特定 pip root、CA 合集或固定 UID 提醒，或安装器推荐容量提醒；解释原因，不预先宣布本次无害。 |
| `[待核对]` | 未匹配已知规则的 WARNING／警告；保留原文，不自动忽略或判成功。 |
| `[错误]` | 明确的安装器错误、APT 错误、权限不足、空间耗尽等；是否失败仍由原退出码和完整成功标记判断，不靠单个关键词覆盖结果。 |

同类提醒解释只显示一次，原警告行不删除。只有基础步骤实际通过，摘要才说明“本次未阻断基础步骤”；遇到后续错误仍显示未完成。不会通过忽略全部 WARNING、放宽权限、关闭 TLS 或更改磁盘保护来美化日志。输出继续脱敏；未修改底层命令返回给解析器的原文，显式参数模式的 `TG2CLOUD_*` 标记保持原样。

确认计划并进入执行后，结束或失败时输出本次摘要。未运行的步骤显示“未执行”，缺少标记或有效记录显示“未核实”；失败显示“未通过”，首次安装的旧配置保留／升级前备份和内网的公网 HTTPS 等显示“不适用”。只读 `--check`、取消计划、仅查看凭据、同版本仅安装管理工具不生成虚构的升级验收摘要。

摘要中的“原 .env 保留”只表示升级后的原文件字节比较，不承诺全部配置、历史任务或 Session 逐项一致；“数据库备份通过”依据本次实际成功步骤收到的备份确认，只证明相应备份检查，不代表服务恢复演练或所有网关授权可恢复。缺失相关标记保持未核实。失败时目标版本不是当前实际运行版本，须重新检查；不未经核实宣称已回退。

入口检查通过后只读取一次所选 Bot 的现有业务观察，命令设置 20 秒超时，超时后的终止清理沿用原有本机执行机制；不轮询或额外请求 Telegram／WebDAV，不绕过认证／限流冷却，不因就绪未确认自动重启或回退。新启动的 Bot 还没有观察、记录过期、版本不符或读取超时显示未核实，不因此将已完成的基础升级改判失败。用户中断执行时不追加该读取。WebDAV 验收失败仍沿用非零退出码和原错误处理。

后续按摘要引导完成：

1. 需要时进入 **10. 业务就绪检查**，核对连接、调度、磁盘；手动暂停／冷却等状态不会冒充通过。
2. 先在网关后台完成云存储挂载和专用账号，再进入 **11. WebDAV 验收**。升级未加 `--verify` 时不擅自执行写入；首次安装与显式 `--verify` 仍沿用原确认，仅创建并清理随机测试文件。
3. 向 Bot 转发一个自有小文件，查看任务详情及结果，并在云存储官方客户端核对。脚本不替用户发送文件，不自动勾选真实转存通过，不新增手动打勾后冒充自动验证的记录。
4. HTTPS 从外部网络另验，内网从另一台可信设备访问；本机检查不替代客户端连通性或视频播放验收。

摘要仅用于本次终端反馈，不持久化原日志、文件名或秘密，不新增生产数据库字段。两个 Edition 分别生成，互不借用另一实例的通过结果。阶段失败时只报告已完成／未完成范围，先核对服务和原回退日志，不重装或删除数据来排错。

### 现有每实例脚本（继续保留）

以 root 登录自己的 Linux 主机后使用已安装的 `manage.sh`，不是在 Git 克隆目录运行。普通用户应先取得管理权限；精简系统不一定安装了 `sudo`，root 不必再加 `sudo`。

| Edition | 安装目录 | Bot 容器 | 网关容器 |
| --- | --- | --- | --- |
| CloudDrive2 | `/opt/tg2cloud-clouddrive2` | `tg2cloud-clouddrive2-bot` | `tg2cloud-clouddrive2` |
| OpenList | `/opt/tg2cloud-openlist` | `tg2cloud-openlist-bot` | `tg2cloud-openlist` |

先做只读状态检查，例如：

```bash
/opt/tg2cloud-clouddrive2/manage.sh status
/opt/tg2cloud-clouddrive2/manage.sh check
```

OpenList 把路径换成 `/opt/tg2cloud-openlist/manage.sh`。子命令含义如下；会写入、重启或删除的项目应先安排维护窗口，不要逐项试跑：

| 子命令 | 影响与 Edition 差异 |
| --- | --- |
| `status` | 查看本 Edition 容器及健康状态；不等于 WebDAV 可写。 |
| `logs` | 查看最近 30 分钟、最多 200 行并持续跟随；OpenList 同时显示网关日志，CloudDrive2 显示 Bot 日志。Ctrl+C 结束查看，不卸载服务。 |
| `recent-logs` | 仅 OpenList，读取同一时间范围的脱敏日志，不持续跟随。 |
| `check` / `doctor` | 核对配置、代码指纹及基础心跳；OpenList 另检查管理页响应，不创建远端文件。 |
| `verify` | 真实创建和清理随机远端测试文件，直接运行时不会追加向导确认。先阅读[验收范围](STORAGE.md#写入验收与成功标记)；推荐按安装指南使用有确认的 `--verify`。 |
| `restart` | CloudDrive2 仅重启 Bot；OpenList **同时重启网关与 Bot**。不重新加载修改后的环境配置。 |
| `restart-bot` / `restart-openlist` | 仅 OpenList，分别重启 Bot／网关；重启网关会影响正在使用它的传输。 |
| `stop` / `start` | CloudDrive2 停止／启动 Bot；OpenList 操作网关和 Bot 两个服务。 |
| `update` | 用本机已安装 payload 重建 Bot，不下载新版本代码、不替换 `.env`；OpenList 还拉取 Compose 已固定的网关镜像并检查两服务。不是完整的 Release 升级向导。 |
| `apply-config /absolute/new-config.env` | 备份、预检、应用完整新配置并重建 Bot；失败尝试恢复原配置。不是只应用一个增量字段。 |
| `backup` | 仅 OpenList，创建业务备份，期间短暂停止网关与 Bot。CloudDrive2 没有同名子命令。 |
| `backups` | 只读统计本 Edition 升级回退点的数量与占用，不显示其内容。 |
| `prune-backups N` | **直接删除**旧回退点，按类型各保留最新 N 份，N 为 1～50，默认 5；无额外交互确认，执行前先独立备份。 |

常规日志尽量脱敏，但文件名、聊天内容或第三方输出仍可能包含隐私，导出前须人工核对。不要通过 `cat .env`、公开完整容器环境或贴出 `rclone.conf` 来排查。

## 修改运行配置

先处理已有队列和失败保留任务，尤其不要在有未完成任务时直接切换云盘账号或目标路径。用匹配版本的配置格式准备**完整**新配置，放在实例目录之外的私密绝对路径，限 root 读取；不要写入仓库、Shell 历史或公开日志。

以下命令会重建 Bot 并执行真实写入验收，只在已准备完整配置且同意这些操作后运行：

```bash
/opt/tg2cloud-clouddrive2/manage.sh apply-config /root/private/new-config.env
/opt/tg2cloud-clouddrive2/manage.sh check
/opt/tg2cloud-clouddrive2/manage.sh verify
```

OpenList 使用对应安装路径。单纯 `restart` 不会应用新环境值；`apply-config` 也不替你在网关后台创建用户或更新密码，两边必须一致。失败后核对旧配置和容器状态，不把“已尝试回退”当作全部恢复成功。

## 升级与备份的操作边界

正式升级统一使用 [VPS](VPS-INSTALL.md)／[LAN](LAN-INSTALL.md)入口，卸载另见[独立卸载指南](UNINSTALL.md)。不要为升级先卸载，或把 `manage.sh update` 当成在线下载新版。

业务回退点位于 `/opt/tg2cloud-clouddrive2-backups` 或 `/opt/tg2cloud-openlist-backups`；部署只统计占用，超过 5GB 提醒，不自动清除。`prune-backups` 仅处理当前 Edition 下的受管 `config-*`、`database-*`、`env-*`、`openlist-state-*` 普通文件，不清理 TG115、下载或云端文件；它与卸载的数据清理模式不同。

第一次升级和实际文件验证之前，不急于删除旧回退点。备份范围、Session 与网关授权缺项、离线快照及恢复预检统一见[备份范围](RECOVERY.md#备份范围必须区分)，共享代理维护见本页下方。备份目录为私密目录，包含配置或授权数据，不能公开上传；不要把“归档可解包”解释为已经验证服务可以恢复。

## 查看实际运行版本

公网实例先运行公开安装入口的 `--edition clouddrive2 --check`（OpenList 改为 `openlist`），核对实际版本、源码和 HTTPS；内网实例使用 `install-lan.sh` 对应参数。命令全文与安装/升级区别见 [VPS 指南](VPS-INSTALL.md)。`--check` 不执行升级，`manage.sh update` 只重建本地已有 payload；两者都不能替代升级后的实际转存检查。

当前源码重构保留已部署的 `app.*` 运维命令、数据库和 Session 路径；新核心由 `app/tg2cloud/` 加载，新递归指纹有显式 v2 前缀，旧实例按历史协议与正式清单核对。目录调整不自动升级运行实例，也不要求迁移数据库。开发检查及发布门槛见[Linux 重构说明](development/LINUX-REFACTOR.md)。

通过 `tg2cloud` → **2. 查看运行状态**区分管理工具来源版本、实际实例版本及容器健康；不要用下载文件名代替运行版本。服务器版本高于 latest 时不自动降级，无法识别官方基线时停止，不把探测失败当作未安装。容器健康仍不代表 WebDAV 写入通过。

## 部署阶段与失败提示

Linux 向导依次输出源码核验、实例／资源检查、确认计划、基础安装或候选升级、入口检查与独立写入验收等阶段；具体结果标记见 [VPS 指南](VPS-INSTALL.md#https-续做与验收)，没有 Windows 弹窗或猜测百分比。

先记录“在哪个阶段失败”，再看实际错误。`--check`、基础服务、HTTPS、WebDAV 和真实转存是不同证据；缺工具不一定是 DNS 错，认证失败也不应靠重新签证书解决。中断后先核对当前状态与备份，不假设已自动回滚，也不重复卸载／重装。

## OpenList 限流诊断

Bot `/doctor`（运行诊断）显示 OpenList 最近实际探测时间、认证错误/限流状态及下一次允许探测的剩余时间。主状态页面保持原有简洁样式。

- HTTP 401：核对 OpenList 专用 WebDAV 用户与 VPS 配置；只读探测冷却 5 分钟。
- HTTP 429：停止重复点击；只读探测退避为 60、120、240、480、900 秒，最长 15 分钟。
- 刷新诊断不会绕过冷却，也不会把消息刷新时间当成真实探测时间。冷却结束只是允许重新检查，并不保证服务端已经解除限流。
- 显式 WebDAV 写入验收仍是独立流程，不使用该只读缓存。

## 共享 HTTPS 代理维护

两 Edition 共用 `/opt/tg2cloud-proxy`；业务备份不包含此目录，代理必须单独备份。用 `tg2cloud` 的 **HTTPS 管理入口**检查、修复和续期 dry-run，用**备份管理**备份、列出、核验／隔离解包最近归档及清理；正式 v1.4.3 为 6／7，v1.4.4 菜单为“7. HTTPS 与管理”／“13. 数据备份管理”。下面描述能力，不是另行提供同名命令行子命令。

| 操作 | 范围与限制 |
| --- | --- |
| 备份共享代理 | 保存两个 Edition 的域名状态、Compose/Nginx 配置、完整 Let's Encrypt 目录及续期记录；不停止 Bot，不回传备份。 |
| 核验最近代理备份 | 检查最近由此工具生成的备份 SHA256、内部文件清单和各文件校验。 |
| 隔离恢复演练 | 解包至新建私密测试目录，检查内容后清理该测试目录；不覆盖运行配置、不启动服务、不替换证书。 |
| 续期演练（dry-run） | 仅对当前 Edition 的已配置域名测试 ACME 续期；不替换正式证书，不启用 deploy hooks。 |
| 管理历史代理备份 | 当前菜单列出归档并校验／隔离解包最近一份；预览确认后清理旧备份，固定保留最近 5 份有效备份。 |

手动 dry-run 不使用自动续期的随机等待，并禁用目录 hooks；自动续期仍保留原有随机等待策略。Certbot 可能执行证书续期配置中已有的 pre/post hooks，修改过 Certbot 配置的用户应先核对这些命令；演练不是完全无写入的操作，可能产生测试账户与日志，但不保存测试证书。

一次性续期演练的执行上限为 9 分钟，超时后给予 15 秒退出宽限，并检查、清理本次唯一命名且任务／角色标签匹配的容器，不停止共享代理或 Bot。备份操作上限为 150 秒；普通中断尝试清理本次未完成归档或隔离目录。执行时限不等于总耗时，退出与清理还需时间。SSH 中断、强制杀进程或 Docker 无响应时不能保证清理，重新连接后先核对，不反复启动演练。

备份及其校验文件仅保存在 VPS `/opt/tg2cloud-proxy-backups/`，目录权限 700、文件权限 600。包含证书私钥和 ACME 账户数据，不要上传 GitHub、公开网盘或工单，不要导出至源码仓库。工具不自动删除历史备份；定期检查 VPS 空间并自行安排离机的私密备份。

当前菜单清理固定保留最近 5 份有效备份：先列拟删除文件，再确认，默认取消。底层历史接口支持的其他保留份数不等于当前菜单已有可调选项。候选归档须完整性通过，仅删除已确认清单及对应校验文件，不递归处理无关目录。预览后文件变化则停止；删除不可撤销，中断可能部分完成，须重新核对，不能假设自动回滚。

备份覆盖整个共享代理而非单一 Edition。维护使用同一 VPS 事务锁；若证书续期同时修改源文件，备份会拒绝不一致快照并移除本次未完成的归档，稍后再试。隔离解包通过只证明备份内容可读、校验一致，不代表灾难恢复后的服务启动已经验收。当前不提供一键覆盖运行实例的 Restore。

## 续期记录与到期提示

检查 HTTPS 状态时可查看每个域名最近续期检查、最近检查成功、最近证书文件变更和预计下次检查时间，统一显示 UTC。Certbot 仍每 12 小时检查，Nginx 仍每 6 小时重载；证书剩余不足 22 天时显示提醒，既有严格证书验证继续保留。

最近自动续期检查失败，或已有记录超过 26 小时没有更新时，显示黄色“HTTPS 可用，续期待检查”警告。当前 HTTPS、证书和安全自检仍通过时，管理页与 WebDAV 验收入口保持可用；这不代表续期故障已解决。旧实例完全没有记录只显示“尚无记录”，不会据此误报续期失败。时间异常时请核对 VPS 时钟和续期容器。

Certbot 检查成功可能表示证书无需续期，不能写成“已续签”。旧实例尚无记录时显示“尚无记录”；需要更新续期容器时，使用匹配的新工具显式续做同一 HTTPS 域名，不因下载入口自动生效。续期 dry-run 成功不代替长期自动续期与重载验收。[Certbot 官方说明](https://eff-certbot.readthedocs.io/en/stable/using.html#renewing-certificates)

Let's Encrypt 已于 2025 年 6 月 4 日停止证书到期提醒邮件；填写邮箱不能替代续期监测。TG2Cloud 不增加外部监控、统计或遥测。[Let's Encrypt 官方公告](https://letsencrypt.org/2025/06/26/expiration-notification-service-has-ended)

## 公网检查与验收边界

VPS 本机 HTTPS 自检不能证明公网可访问或后端端口在外部网络不可达。请从独立网络验证 HTTPS、HTTP 跳转、`/dav` 与 `/dav/` 阻断，以及 IP 加管理端口不可达。参见 [HTTPS 验收清单](development/DOMAIN-HTTPS-ACCEPTANCE.md)。测试不得复用生产 Bot 凭据，不得把网关通过当成 Telegram/真实网盘转存全链路通过。
