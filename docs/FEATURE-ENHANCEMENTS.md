# 文件分类、异常通知、成员配额与诊断

这些设置均为当前 Bot 的可选能力。默认分类、主动通知关闭，管理员及已有成员默认不限额。使用前同时核对 Bot 与离线 CLI 版本，更新文档不会更新服务。

主菜单分别提供 **8. 文件分类设置**、**9. 异常通知设置**、**5. Bot 用户管理**、**12. 故障诊断报告**；参数逐项输入，不要求手写复杂规则。数据库、Session 与回退说明见[配置](CONFIGURATION.md)和[备份](BACKUP-RESTORE.md)。

## 默认行为

分类、主动通知默认关闭；管理员和已有家人默认不限额。继续Linux Python+Bash、CloudDrive2/OpenList、AMD64/ARM64，不增加端口、容器权限、主安装问题或Bot首页按钮。不改命名、去重、取消确认、代理和后端提交策略。

设置在当前实例业务数据库，不修改`.env`、rclone配置或网关账号。镜像新增系统时区包`tzdata`，无新增Python/npm依赖，不换固定镜像。

## 智能分类

正式 v1.4.3：`tg2cloud` → 选择 Edition → **14 分类 / 异常通知设置** → **1 分类规则**。v1.4.4：主菜单 **8. 文件分类设置**直接列出全部五种规则，选择后确认保存；0 返回，不改设置。

| 规则 | 相对原Bot保存目录的示例 |
| --- | --- |
| 不分类（默认） | `原名.mp4` |
| 按类型 | `视频/原名.mp4` |
| 按年份 | `2026/原名.mp4` |
| 按年月 | `2026/10/原名.mp4` |
| 按类型/年月 | `视频/2026/10/原名.mp4` |

类型为视频、图片、音频、文档、压缩包、其他文件。优先Telegram媒体类型/MIME，真实扩展名兜底，不修改文件名和冲突编号。日期按接收时间及实例`TZ`确定，分类目录持久化；媒体组共用日期/规则快照，混合图片/视频按类型各入对应目录。

重试、重启和换名恢复沿用原目录；设置改变只影响新任务。旧任务分类目录为空，不整理历史云端文件。仅接受程序生成的受管相对目录，禁止绝对路径、`..`、反斜杠及编码穿越。CloudDrive2临时对象仍在旧扫描范围，验证后改名；OpenList继续预留正式路径直接写入。目录创建失败不静默回退到根目录。接收后基础目录变化时停止自动恢复，要求核对配置。

## 主动通知

`tg2cloud` → **9. 异常通知设置**直接提供异常通知开关、恢复通知开关和磁盘提醒阈值，开关文字随实际状态变化。选择阈值后直接输入 GB，`0` 跟随原安全线，不能降低原磁盘保护；恢复通知仅在异常通知总开关开启时生效。保存前确认，锁内复核实例并校验配置 revision，不重启 Bot。只给唯一管理员发固定原因、影响、建议、Edition 和时间，家人不会收到系统信息。

`service_meta`中的`optional-features.v1`配置默认如下，通过菜单设置，不直接编辑数据库：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `classification` | `off` | 另有`type/year/month/type_month` |
| `timezone` | 实例`TZ`，缺省`Asia/Shanghai` | 日期及个人计量时区 |
| `notifications` | `false` | 主动通知开关 |
| `recovery_notifications` | `true` | 通知开启后是否提醒恢复 |
| `disk_threshold_bytes` | `0` | 与原安全线取较大值 |
| `cooldown_seconds` | `1800` | 同类告警/发送未确认冷却 |
| `sustained_seconds` | `300` | WebDAV持续异常观察 |
| `blocked_seconds` | `1800` | 资源等待持续观察 |

覆盖磁盘安全线、任务需人工处理、WebDAV认证/权限错误、持续不可用/限流及资源等待。每15秒读取已有观察，不追加WebDAV请求、不绕过401/403/429冷却、不因查询`/doctor`而报警。故障/尝试持久化；过期样本不宣称恢复，每次故障结束最多一次恢复通知。

Telegram发送不能和SQLite原子提交：先记录尝试再发送，断电/超时结果不确定时冷却，不承诺严格恰好一次。Bot退出、容器停止、完全断网时不能保证通知；本轮不新增宿主监控或证书提醒。

## 家庭成员配额

`tg2cloud` → **5. Bot 用户管理**，选择已登记家人的配额操作。可设置每日GB、最大排队、最大同时传输，`0`不限，可取消限制。管理员不能在此菜单给自己设限，不额外授权陌生ID。家人发送**`/quota`**只看自己的用量，不能查询或修改他人额度。

当前菜单直接提供 **5. 查看成员配额**、**6. 设置成员配额**、**7. 取消成员限额**；先选动作再选家人，查看只读，设置直接填写三项额度后确认，取消需确认，不再进入额外配额菜单。

排队含`queued/downloaded/waiting_upload`；同时传输含放行下载、普通上传、流式、验证/提交。一个流式占一个个人槽，仍受原全局下载/上传窗口限制。

登记和预留在同一`BEGIN IMMEDIATE`事务完成，重复转发不重复预留；大小未知仍拒绝登记。待处理和失败保留任务持续预留已知大小，重试不重复；取消未完成任务才释放。WebDAV复验后进入清理/完成时计量一次，不等于哈希验证或云盘官方最终完成。

按配置时区的本地日历日统计完成量，跨日保留未完成预留。可用量=`每日额度−今日已完成−全部未完成预留`，最低零。降低额度不取消已接收或运行任务，新登记/恢复检查对应限制，新阶段检查并发。旧未完成任务迁入预留，旧完成历史不追溯计量。不按网络重传字节收费，不统计全部网关缓存/云端占用。

## 诊断报告

当前：`tg2cloud` → **12. 故障诊断报告**。只读展示后确认保存，默认`/opt/tg2cloud-reports`，目录0700、随机文件名0600，不自动上传、不重启、不安装软件、不做WebDAV写入。

白名单含版本、Edition、宿主平台/架构、Docker/Compose、容器状态、近期业务观察、空间/预算及最近7天当前失败任务分类数量；不是原始日志/全部历史错误。配置只检查字段存在，不显示值或证明凭据有效。未知项目不判通过。诊断报告中复用只读 HTTPS/LAN 检查并给出固定处理建议，终端与 Markdown 导出分别渲染；入口修复仍须进入主菜单 7 并确认，不在诊断中自动执行。

不含聊天内容、原文件名、用户ID、完整路径、环境变量、Session或Token。分享前仍自行审查。

## 数据库与回退

当前业务库为 schema 3，包含分类、配额与监听数据；旧版升级按事务依次迁移，保留任务、状态和 Session。设置复用 `service_meta`，两 Edition 数据库独立。

升级前保存旧程序及同一时刻数据库快照。不能用不支持当前 schema 的旧镜像直接降级。回退先停止所选Bot，另存当前数据库，再人工选择升级前已核验快照和匹配程序；旧快照不包含升级后的新任务。不提供删表降级或自动生产恢复。需更新Bot容器和管理工具，之后改设置/配额无需重启，旧`.env`无新必填项。

发布与实机验收分别记录，结果见[当前发布记录](development/V154-ACCEPTANCE.md)；现有实例须显式升级才能获得对应能力。
