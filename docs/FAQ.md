# 常见问题

适用于当前正式 Linux v1.4.3；旧版本的行为差异另有说明。本文给排查方向，完整命令和风险集中在链接的专题，不重复维护另一套操作流程。

## 安装和升级

### 升级出现 WARNING 需要处理吗？

v1.4.4 源码增加日志分类和逐项结果摘要：常见构建提醒只解释，未知 WARNING 标为待核对；只有原命令和校验通过才记录通过，不屏蔽错误。旧 v1.4.3 工具仍是原显示，须显式升级离线管理工具才生效，见[日志与摘要说明](OPERATIONS.md#安装日志与结果摘要v144)。

先看具体内容和最终结果，不以单个 `WARNING` 判定失败，也不要一概忽略。2026-10-23 用户提供的 CloudDrive2 v1.4.2 → v1.4.3 日志中，下列提示未导致升级失败：

| 提示 | 含义与处理 |
| --- | --- |
| `Running pip as the 'root' user` | pip 默认对 root 安装发出提醒。本项目该步骤位于 Docker 镜像构建中，不是在宿主 Python 环境装 Bot 依赖；正式镜像／Compose 配置为非 root `10001:10001`。不需要为此在 VPS 上重装 Python 或改容器为 root。见 [pip 官方说明](https://pip.pypa.io/en/stable/cli/pip_install/#cmdoption-root-user-action) |
| `skipping ca-certificates.crt` | CA 合集包含多张证书，不适合作为 rehash 的单证书索引对象；这条提示本身不是域名证书错误。只有这条提示、包安装成功且后续 TLS 检查正常时无需删证书。见 [OpenSSL 说明](https://docs.openssl.org/3.0/man1/openssl-rehash/) |
| `uid 10001 is greater than SYS_UID_MAX 999` | 固定容器 UID 超出系统账号默认编号范围的提醒，账号仍可成功创建；不表示 Bot 以 root 运行，不需改动已有文件归属 |
| 总容量低于推荐 50GB | 是推荐总容量，不是硬性门槛。仍须通过容量校验并留意暂存、备份、Docker 和网关缓存，不能因此忽略后续空间不足 |

本次日志最后有 `TG2CLOUD_VERSION=1.4.3`、`TG2CLOUD_CODE=OK`、`TG2CLOUD_BOT_HEALTH=healthy`、`TG2CLOUD_RESULT=SUCCESS`，并通过本机 HTTPS 检查，支持“基础升级成功”。真实转存和公网访问仍单独验收，详见[本次脱敏记录](development/V143-ACCEPTANCE.md)。

如果还有依赖安装失败、`Permission denied`、`No space left on device`、TLS 校验失败、容器不健康或 `TG2CLOUD_RESULT=FAILED`，按具体错误排查，不照搬上述解释。不要通过关闭证书校验、放宽到 `chmod 777` 或屏蔽全部警告解决问题。

### Oracle 的 A 记录正确，为什么 HTTPS 预检仍失败？

如果网卡仅显示私有 IPv4、域名解析到云控制台的公网 IPv4、80／443 没有监听者，可能是 v1.4.0 未兼容公网 NAT 的地址比对。不要把域名改成私有 IP。正式 v1.4.1 和匹配 helper 已增加人工核对云控制台公网 IPv4、分项错误提示与执行前复查；重新运行公开入口，旧离线工具需显式更新。条件、确认范围和发布边界见[VPS 指南](VPS-INSTALL.md#公网-nat-的已知限制与待发布修复)。确认地址后仍需通过 ACME，防火墙／安全组及实际入站连通性须独立核验。

### curl 命令可以单独安装吗？

`curl -fsSL https://raw.githubusercontent.com/LuoPoJunZi/TG2Cloud/main/install.sh` 只把脚本文本输出到终端，不安装。要进入向导，请使用 [VPS 指南](VPS-INSTALL.md#vps-单行安装命令)中的完整 `bash <(curl …)` 命令。下载失败、只显示版本或退出码 0，也不能代替最终验收。

### APT 报没有 Release 文件怎么办

先在自己的终端运行 `apt-get update` 核对系统原始错误。v1.4.1 用户此次实际遇到的是 Ubuntu 安全源 URI 缺少主机名，不是 ARM64／NAT 不支持；源文件和 APT 日志的斜杠格式还可能不同。应备份并只修正确认错误的活跃条目，不关闭安全检查或整份覆盖源列表，详见[APT 排查](VPS-INSTALL.md#apt-软件源错误)与[本次验收记录](development/V141-ACCEPTANCE.md)。不要上传含凭据的源配置或安装汇总。

### --check 输出 OK，是否升级成功？

不是。它检查当前实例、源码基线、容量和现有入口并展示计划；不停止服务、不替换程序。确认后实际运行安装／升级，再核对 Bot 版本、健康和转存。`--verify` 则会写测试文件，不能与只读预检混淆。

### 能在任意 NAS、ARM 或 Docker Desktop 安装吗？

正式 v1.4.1 继续支持 Debian/Ubuntu 原生 AMD64 / ARM64，匹配的稳定源码和 helper 已发布，两个原生 runner 的 CI 已通过。要求 root、64 位用户态和本机 rootful Docker，内网另要求 Docker 28+；不会默认使用 QEMU，不支持 Docker Desktop。DSM／QTS 等不保证可直接运行，可使用符合条件的 Linux 虚拟机并填写虚拟机自身 IP。用户已完成一台 Ubuntu26.04.1 ARM64 公网NAT 的 CloudDrive2 首装／本机HTTPS／WebDAV验收，不扩展为任意系统或全部转存通过，见[双架构说明](ARCHITECTURES.md)。

### 更新仓库、运行管理菜单、重启容器，会自动更新 Bot 吗？

不会。在线向导 helper、正式业务 Release、实例 Bot 和独立 WebDAV 离线工具是不同更新对象。`tg2cloud` 状态／日志不下载更新，`manage.sh update` 只重建本机 payload。正式业务升级走 [VPS](VPS-INSTALL.md#已有实例升级)／[LAN](LAN-INSTALL.md#已有实例与升级)流程，附加工具单独 upgrade。

### 为什么基线不一致会停止？

版本文字相同不保证程序与正式版一致。额外／缺失文件、手改 Compose、未知容器或旧 TG115 都不能自动接管。不要改版本号、删 Session 或关闭指纹校验；先备份并人工审阅差异。见[基线处理](VPS-INSTALL.md#源码基线不一致时)。

### 原版本 Release／Tag 被删除，还能升级吗？

v1.4.3 已为 v1.3.4／v1.4.0／v1.4.1／v1.4.2 补充可信原提交／载荷目录，详见[基线说明](development/MAINTENANCE-IMPROVEMENTS.md#1-旧版本可信基线)。仍须逐文件核验实例，未知版本、手改源码和镜像变化不自动放行。

未被可信目录覆盖、且缺少正式基线的旧版本仍会停止。保留现有服务，按[缺失旧版基线的处理](VPS-INSTALL.md#旧版本-releasetag-已删除)备份并单独审阅可追溯原提交；不要改版本标记或卸载重装。历史 [v1.3.4 → v1.4.2 人工升级](development/V142-ACCEPTANCE.md)不作为本版自动升级的实机验收。

## 管理页与 WebDAV

### 管理域名能打开，但 /dav 返回 403，是错误吗？

管理域名主动阻断 `/dav`，这是预期边界。Bot 使用 Docker 内部 WebDAV 地址；手机读取需要单独安装[外部 WebDAV](external-webdav.md)，使用另一个域名和独立只读账号。不要把 Bot 凭据填入公共管理 URL 尝试放行。

### 只添加 A 记录，为什么 HTTPS 仍可能失败？

A 记录正确只是条件之一；残留错误 AAAA、Cloudflare 代理、解析未生效、80/443 被其他项目占用、防火墙或 ACME 签发问题都可能阻止配置。先看实际失败阶段；当前脚本不自动停止未知代理或删除 AAAA，详见 [HTTPS 续做](VPS-INSTALL.md#https-续做与验收)。

### 本地目标目录到底填什么？

向导的 Bot 保存子目录相对于 WebDAV 账号根目录，不是 `/opt/.../downloads`。用户根目录在网关后台设置；两处不要重复填写。外部 WebDAV 还需确认最终网关逻辑目录，手机根路径固定 `/dav/`，四者不同。见[目录组合](STORAGE.md#根目录与子目录只组合一次)。

### healthy、HTTPS 正常、WebDAV OK 分别证明什么？

healthy 证明基础心跳；HTTPS 自检证明本机入口／证书等检查；写入验收检查 Bot 到目标 WebDAV 的必要操作和大小。三者都不单独证明实际 Telegram 转存、内容哈希或云盘官方最终入库。应分别从外部网络和云盘客户端验收，见 [STORAGE](STORAGE.md#写入验收与成功标记)。

## Bot 和任务

### 两个用户 ID 一起填写就能共用 Bot 吗？

不能。安装只填一个固定管理员 ID；之后用 `tg2cloud` → **Bot 用户管理**授权家人（正式 v1.4.3 为 10，v1.4.4 新菜单为 5）。成员各自管理任务，共用目录与资源；不是个人文件夹隔离。手机访问授权是另一套独立账号，见[家庭共享](FAMILY-SHARING.md)。

### 为什么数字名视频仍没有变成标题？

Bot 可能没收到图片上的说明；原名可能被保守判为有意义；候选也可能全部是网址／话题／推广。不要假设它可以读取评论、源频道或视频画面。先看[命名指南](NAMING.md)，并核对实例是否已升级到 v1.3.4。新规则不会追溯改名已登记任务，不能靠重复转发绕过去重。

### 没任务时“下载 1，上传 1”是卡住了吗？

诊断中的并发窗口是允许放行额度，不是活动数；空闲时也可为 1。实际任务看首页。资源页的“本地”是 Bot 暂存额度，“磁盘”是对应文件系统剩余容量，不能当成网盘容量或全部网关缓存。

### 为什么失败数量还在？每周清零会删任务吗？

`❌ 数字` 按 Bot 时区的本地日历周统计仍失败的任务；每周一刷新后切换范围，不是滚动七天或删除历史。修复成功的任务不再计入，本周仍失败则保留；历史可查 `/tasks failed`。见[失败计数](RECOVERY.md#首页失败计数)。

### 文件一直排队或无法取消后重发怎么办？

先 `/doctor` 看手动暂停、目的端、冷却与资源，再 `/task 编号` 看状态。已取消文件需显式重新转存确认；清理未结束或远端不确定时不能直接重启。不要通过删除历史库或连续转发绕过去重。见[任务恢复](RECOVERY.md)。

### OpenList 上传失败，为什么不自动删掉远端残留？

无法确定那个对象是否完整或被外部修改，自动覆盖／删除会危及数据。确认后 `/recover 编号` 选择新路径，旧对象保留。OpenList 直接写最终路径，与 CloudDrive2 临时对象＋改名策略不同，不能强套 MOVE。见[冲突恢复](RECOVERY.md#上传中断或远端冲突)。

### 超过 20GB 的文件需要先扩大磁盘预算吗？

不一定。超过预算的单文件可走流式，普通小文件也受预算和真实剩余空间约束；流式仍消耗缓冲、网络和网关资源，没有完整本地副本，失败通常需从头读取，并非字节级续传。不要降低 8GB 安全线换速度。

## 备份、卸载与求助

### 升级回退包就是完整备份吗？

不是。它可能不含 Session、下载、网关授权、HTTPS 或附加元数据。恢复预检也只证明结构／DB，不证明服务可用。按[备份范围](BACKUP-RESTORE.md#现有备份的实际覆盖)组合备份，并保存私密离机副本。

### 卸载一个 Edition 会影响另一个吗？

正常受管卸载只操作所选 Edition；另一套的数据和 Bot 保留，共享代理更新可能短暂重载。默认会清理所选数据及可识别备份，保留数据须明确 `--keep-data`。先处理外部 WebDAV 依赖，不使用全局 Docker prune。见[卸载指南](UNINSTALL.md)。

### 为什么卸载后还留着工具或少量锁文件？

仍有另一实例、保留数据／备份、附加路由或未知资源时，会保留工具以避免误删。锁元数据、系统软件、Docker 缓存和系统日志不属于“恢复原状”的保证。部分失败后先重新只读预检，不递归删除 `/opt`。

### 反馈问题时提供什么？

提供 Edition、实际 Bot／管理工具版本、Linux／Docker 版本、执行的非秘密命令、失败阶段和脱敏错误。命名问题加合成原名／说明；网络问题说明是本机还是外部网络。不公开 `.env`、rclone 配置、Session、数据库、完整容器环境、私人文件或备份。
