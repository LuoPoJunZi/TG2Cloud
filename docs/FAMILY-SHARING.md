# 家庭共享（v1.3.3）

v1.4.3 支持菜单 10 → 5 的配额／用量，以及家人私聊 `/quota`，默认不限额；见[使用与计量规则](FEATURE-ENHANCEMENTS.md)。已有 Bot 和管理工具需同步升级。

v1.4.4 菜单把 **Bot 用户管理**移至主菜单 5，并在其子菜单直接提供“查看成员配额”“设置成员配额”“取消成员限额”；选择成员后直接执行查看或填写额度，不再增加配额操作菜单。正式 v1.4.3 仍是原编号，新 UI 须后续发布并更新离线工具才会生效。

本功能由 [v1.3.3 Release](https://github.com/LuoPoJunZi/TG2Cloud/releases/tag/v1.3.3) 提供；v1.3.2 及更旧版本没有这些菜单。在线安装仍只获取正式稳定 Release；已有 Bot 实例、本地管理工具与独立 WebDAV 离线工具需分别显式升级。

## 范围

安装时仍只输入一个 Telegram 用户 ID，作为固定管理员；不能输入多个 ID。之后可以授权最多 32 位可信家人，各自私聊同一个 Bot 转存文件，共用已有保存目录、磁盘预算和调度额度。不创建个人目录，不修改 Bot 的 WebDAV 账号、rclone 配置或网关挂载。

Bot 成员和外部 WebDAV 是两套独立授权：前者提交文件，后者在手机上读取共同目录。添加或移除一边不会自动改变另一边，账号和密码也不复用。

## Bot 成员管理

在已升级至 v1.3.3 或更高版本的 Linux 主机运行 `tg2cloud`，明确选择 Edition，再按名称选择 **Bot 用户管理**。依次可查看、添加、启用、停用或移除家人授权。输入家人的数字 ID 和备注，确认计划后生效，无需重启 Bot。管理员不能通过此菜单被移除或改成普通成员；旧 Bot 不支持管理协议时会停止，需先按正式流程升级，不能直接编辑其数据库代替升级。

家人仅能查询、搜索、重试、恢复、取消和人工确认自己的任务，完成通知发给提交者。其他人的编号或旧按钮不会获得任务详情。家人首页保留简洁样式，任务数、失败数及速度只统计本人；`🌐` 是本人下载与上传速度之和，不是宿主机网卡速度。每周失败计数仍只过滤显示，不删除历史。

全局暂停／恢复、诊断、远端临时文件巡检与清理、VPS 资源页仅管理员可用。Telegram 原生命令菜单可能仍列出这些命令，但成员调用会被拒绝。管理员首页沿用全局统计，任务列表仍是自己的任务，不增加代管其他人任务的入口。

停用／移除只撤销新的 Bot 操作和后续通知、订阅，不删除任务、文件或 Session。此前已接收的任务仍会按原队列继续处理。需要取消某项任务时，应在撤销授权前由本人处理。重新授权同一个 ID 后仍可查看自己的历史任务。两版实例的授权互不共享。

注意：这不是个人云盘隔离。任务私聊隔离不等于共同目录中的文件隔离；有读取权限的家人可以看到该目录中的全部文件。

### 添加第一位家人

1. 管理员先完成自己的小文件转存，确认共同目录正确。
2. 让家人提供 Telegram 数字 ID；不要填写手机号、`@用户名` 或 Bot ID。
3. 主机终端运行 `tg2cloud` → 选择 Edition → **Bot 用户管理** → **1. 添加家人**。
4. 填写数字 ID 和备注，核对对象并确认；无需重启 Bot。
5. 家人打开同一 Bot 的私聊，发送 `/start` 和一个自有小文件，查看自己的任务及通知。
6. 如果还要在手机看文件，再为这位家人独立配置下节的 WebDAV 读取账号。

备注是管理识别信息，不是登录名或目录名。Bot 必须运行且支持授权协议，新增菜单不会直接修改停机数据库；同时两个管理终端改授权，冲突会停止，刷新列表后再操作。

| 能力 | 管理员 | 家人 |
| --- | --- | --- |
| 提交附件、查看自己的列表／详情／搜索 | 可以 | 可以 |
| 重试、取消、恢复自己的任务 | 可以，仍需适用状态与确认 | 同左 |
| 首页全局统计 | 可以 | 只显示本人统计 |
| 诊断、资源、全局暂停／恢复、遗留扫描与清理 | 可以 | 不允许 |
| 查看／代管其他提交者任务 | 当前没有新增入口 | 不允许 |
| 添加家人、修改主机配置 | 通过 Linux root 管理工具 | 不通过 Bot 提供 |

## 外部 WebDAV 家庭只读账号

先按[外部 WebDAV 指南](external-webdav.md)安装并验收主入口。统一菜单发布并更新本地工具后，使用 `tg2cloud` → 当前 Edition → **15. 外部 WebDAV → 10. 用户管理**；当前正式 v1.4.6 尚无主菜单 15。家人账号功能自 v1.3.3 提供，既有 `tg2cloud-webdav` 菜单及以下显式命令继续兼容，不要求为使用新版统一菜单额外运行安装命令：

```bash
tg2cloud-webdav users --edition clouddrive2
tg2cloud-webdav users --edition openlist
```

两条命令分别选择已有的 Edition，并非需要同时执行。已审阅本地源码可用 `python3 /path/to/TG2Cloud/scripts/run_source.py webdav users --edition clouddrive2`；仍需 Linux root 和已完整部署的测试实例，不能在开发电脑上冒充实机验收。

菜单支持添加、检查、启用、停用、更改密码和移除新增账号的入口授权，最多新增 32 个。后端实际可建用户数量受其版本和会员能力限制；不支持独立只读用户时停止，不降级使用主账号、管理员或 Bot 凭据。

每位家人的账号仍需在 CloudDrive2／OpenList 后台人工创建和核对：根目录／base path **必须直接等于菜单显示的实际共同目录**，只授予 WebDAV 读取／列表，关闭上传、删除、移动、改名及管理。不能另选个人目录。程序确认凭据与本地目录读取，目录隔离及原生只读权限由你在后台确认，不冒充自动权限审计。

同一外部域名和 `/dav/` 接受已启用的专用账号；Nginx 认证文件仅保存各自的强哈希，客户端的同一凭据还须通过后端认证。Bot、管理员及未登记用户不能仅凭后端有效凭据通过此入口。密码不长期明文保存；账号检查及重新启用需要输入当前密码。自动生成仍为 9 位，可自行设置更长的独特密码，遵守后端要求。

停用／换密先撤销所选账号；失败或普通中断后标记需修复并关闭该账号，不回退旧 Bot 凭据，不删除其他账号哈希。修改后核对容器实际读取的新文件，并验证 Nginx 配置后重载。重载可能短暂影响现有读取连接，不重启 Bot、网关或 Docker；已建立的旧读取连接退出不能被当作瞬时原子操作。后台密码的人工修改不能自动回滚。

停用整个入口会关闭所有账号。再次启用仅恢复经过检查的主账号，家人的账号需逐个检查启用。即使 Bot 目录发生变化，也仍允许撤销成员入口；检查／启用遇到绑定变化会停止，不自动扩大范围。存在新增账号时，更改共享域名、主账号或目录必须先移除新增账号的入口授权，防止重新生成配置时丢失权限记录。

移除只删除本功能的访问授权，不删除人工创建的网关账号、共享目录或云端文件。需要彻底撤销后台账号时，由你核对归属后在网关后台自行操作。停止 Bot 授权并不会撤销其手机读取权限，两边都需分别处理。

### 给家人的手机填写什么

每个人使用相同外部域名、HTTPS 443 与 `/dav/`，但填写各自已启用的独立用户名／密码。不要填写管理域名、Bot WebDAV 密码或 Telegram 数字 ID。共同目录是安装时核对的实际网关目录，不在手机另填宿主机 `/opt` 路径。

离开家庭共享时，按需求分别停用／移除 Bot 授权和外部读取授权。若只是禁止继续转存、不影响观看，只处理 Bot 一侧；若禁止观看，只处理对应 WebDAV 账号。停用不自动删除此前任务或电影。

## 备份、旧版本与故障

Bot 授权保存在现有 `data/tg115.db` 的 `service_meta` 元数据中，含绑定的管理员 ID、修订号与最近 100 条授权操作；不新增表或迁移任务结构。既有一致性数据库备份会包含授权。旧 Bot 忽略新元数据，回退后只认原管理员，不会自动开放所有人；切勿把修改 `ALLOWED_USER_ID` 当作管理员迁移，会造成授权绑定不符。

外部账号首次变更后，附加功能的私密 `config.json` 升至 schema 2；共同目录仍只有一份。共享代理仍使用既有 schema 2 和每 Edition 一个认证目录挂载，不新增路由类型。变更前保留配置与共享代理备份；仅代理备份并不包含附加功能整个私密目录，离线灾备应同时保护两者。备份包含账号信息和密码哈希，应按敏感材料保管。

v1.3.2 及更旧附加工具不认识新的账号记录，会拒绝操作，不应手工降 schema 或用旧代码覆盖认证文件。未知状态、冲突修订和未登记哈希均停止；状态／配置显示只是登记信息，检查某个账号不代表所有家人均已验收。断电、强制杀进程或文件系统写入失败不保证自动回滚；`pending`／`needs_repair` 时先撤销所选入口，再逐个检查恢复，不直接恢复旧哈希使其开放。

## 实机验收清单

- 两位真实 Telegram 用户分别提交、查询、重试、取消、收到通知；交叉编号和按钮被拒绝。
- 分别停用 Bot 成员、外部账号，确认互不联动、历史和文件保留；重启后授权仍正确。
- 两版网关各创建两个独立原生只读账号，核对共同根目录，手机分别播放与 Range 拖动。
- 换密／停用一位家人后，另一位仍可读取；无认证、Bot、管理员和旧密码被拒绝。
- 整体停用再启用不自动开放所有家人；验证备份完整性及隔离恢复，不覆盖生产数据库。

以上为待执行实机清单，不代表本地模拟测试已经完成真实 Telegram、网关或公网验收。v1.3.3 已核对可信 helper 提交、入口 pin、远端 CI 与实际源码资产；发布成功不代替这些实机检查。
