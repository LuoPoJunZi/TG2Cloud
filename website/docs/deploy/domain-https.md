# 域名访问与 HTTPS

TG2Cloud 要求受管 CloudDrive2 或 OpenList 使用公网 HTTPS 域名访问管理界面。它不会改变 Bot 与 WebDAV 的 Docker 内网传输路径。

v1.1.0 已在真实 VPS 完成两个 Edition 的强制 HTTPS 与 WebDAV 全流程验收。

v1.1.1 的实机检查覆盖双管理网关 HTTPS 共存、外部访问/跳转/公开 WebDAV 阻断，以及共享事务锁互斥与断锁释放。

v1.1.2 在专用 Debian 13 VPS 验证代理私密备份/核验/隔离解包、OpenList 路由移除后恢复及续期 dry-run；两版各 11 项 HTTPS 自检通过，CloudDrive2 既有域名、配置与容器保持不变。新 Bot/真实网盘转存、401/429 实际恢复、长期续期、完整恢复和独立网络后端端口隔离仍待验收，不把网关检查写成全部转存业务通过。

## 适用边界

- 域名入口只代理管理界面；
- 公网 `/dav` 与 `/dav/` 固定返回 403；
- CloudDrive2 仍只监听 VPS 的 `127.0.0.1:19798`；
- OpenList 仍只监听 VPS 的 `127.0.0.1:5244`；
- Bot 和 rclone 继续使用 Docker 内网 WebDAV；
- 未配置或严格 HTTPS 自检失败时，当前受管 Edition 保持“待配置 HTTPS”，WebDAV 最终验收不会继续；仅续期警告但当前自检通过时入口仍可用。底层 SSH 隧道只保留兼容/应急能力，不再作为普通工作台入口。

两个 Edition 共用 `/opt/tg2cloud-proxy` 中的一套 Nginx 与 Certbot 容器，但必须使用不同域名。Nginx 是唯一监听 80/443 的 TG2Cloud 组件。

## 配置前准备

1. 先执行当前 Edition 的基础部署；容器健康后部署器会自动打开本对话框。
2. 准备一个完整子域名，例如 `cloud.example.com`。
3. 把全部 A/AAAA 记录直接指向当前 VPS。错误 AAAA 会阻止配置。
4. Cloudflare 首次签发证书时使用“仅 DNS”，不需要 API Token。
5. 在服务商安全组和你自行管理的防火墙中开放 TCP 80/443。

部署器不会修改防火墙，也不会停止、覆盖或重配用户已有的 Nginx、Caddy、Apache、Traefik 或其他端口占用进程。

## 在部署器中配置

打开右侧“部署工作台”中的“配置 HTTPS 管理入口”：

1. 填写纯域名，不要填写 `https://`、端口、路径、通配符或 IP。
2. 可选填写 Let's Encrypt 邮箱；其到期提醒邮件服务已停止，填写邮箱也不能替代续期监测。
3. 点击“检测环境”。
4. 全部检查通过后点击“配置 HTTPS”。
5. 点击“检查状态”，确认 HTTPS、HTTP 跳转、证书、Nginx、自定义 Host、防止公网访问 `/dav` 和后端回环监听均正常。
6. 点击“打开域名管理页”访问 `https://你的域名`。

配置会先启用只服务 ACME challenge 的临时 HTTP 路由，然后签发或复用证书，执行 `nginx -t` 和真实请求自检，最后才写入正式状态。新域名失败时旧域名保持有效；为第二个 Edition 配置失败时，不会删除第一个 Edition 的路由。

## 配置中断与宿主工具

v1.1.5 对 Ctrl+C、TERM 和 HUP 增加有限回退；状态提交与回退期间延后处理重复信号，已提交状态不再恢复成旧运行配置，另一 Edition 的路由继续保留。关闭窗口、网络断开或强制杀死进程不等于正常取消，不能保证远端立即完成回退；重新连接后先检查状态，不要连续重配或删除证书。

预检会明确报告缺少的宿主工具，并为 Debian/Ubuntu 给出安装命令，不再把工具缺失笼统当作 DNS 失败。预检不自动安装软件；执行基础部署时仍复用已有 APT 依赖检查，可能更新相关系统软件包。

## 本机自检与公网验收

部署器的 HTTPS 请求自检从 VPS 回环地址访问 Nginx，并使用真实域名验证证书；这样不会把 NAT 回环限制误判为域名故障。

**本机检查通过不等于公网 443 已经可达。** 配置后仍需从 Windows 浏览器或其他外部网络打开 HTTPS 管理页，确认 HTTP 跳转和公网 `/dav`、`/dav/` 返回 403，并检查 VPS IP 加 19798/5244 端口不能访问。若本机通过但外部失败，应检查安全组、防火墙、DNS 和 Cloudflare 配置，不要公开后端端口或跳过证书校验。

## 自动续期与状态记录

Certbot 容器每 12 小时检查续期，Nginx 容器每 6 小时安全重载一次证书。两者都不挂载 Docker Socket，不依赖宿主机 cron、systemd、apt 或 snap。

从 v1.1.2 起，状态小日志框显示每个域名最近续期检查与结果、最近检查成功、最近证书文件变更及预计下次检查时间，时间统一为 UTC。**检查成功不等于已续签**：证书仍有效时，Certbot 可以成功退出而不更新证书。

最近检查失败、已有记录超过 26 小时未更新、证书剩余不足 22 天或时间异常时，部署器显示黄色“HTTPS 可用，续期待检查”等警告；当前证书与严格安全自检仍通过时，管理页和 WebDAV 验收入口保持可用，不代表续期问题已解决。

旧实例完全没有记录只显示“尚无记录”，不会据此误报续期失败。用新版部署器重新配置同一域名，才能更新续期容器与记录能力；仅下载 EXE 不会自动生效。Let's Encrypt 已停止到期提醒邮件，不论是否填写邮箱，都应自行查看状态与到期时间。

## 维护工具与续期演练

对话框底部的“维护工具”适用于两个 Edition。共享代理备份、核验、隔离解包和历史清理的范围见 [备份与恢复边界](/operations/backup/)；不要与 OpenList 业务安全备份混用。

“续期演练（dry-run）”只测试当前 Edition 已配置的域名，不替换正式证书，不启用 deploy hooks。手动演练取消随机等待并禁用目录 hooks，自动续期策略保持不变。已有证书续期配置中的 pre/post hooks 仍可能执行；修改过 Certbot 配置时先核对，演练可能写测试账户和日志，并非完全只读。

一次性演练远端执行上限为 9 分钟，另有 15 秒退出宽限和精确容器清理；不会停止共享代理或 Bot。SSH 中断或 Docker 无响应时会提示清理尚未确认，重新连接后先核对，不要假设断连即完成清理或反复启动演练。dry-run 通过不代替长期自动续期与 Nginx 重载验收。

## 更新或移除

在同一对话框填写新域名并配置，可以更新当前 Edition。只有新证书和全部自检通过后才提交。

“移除域名访问”只删除当前 Edition 路由。另一个 Edition 继续工作；移除最后一个路由后共享代理容器停止。证书文件默认保留，避免误删和短时间重复签发。被移除路由的 Edition 会立即恢复“待配置 HTTPS”，重新配置并通过全部自检后才能再次显示部署完成。

v1.1.1 为配置/移除增加共享事务锁，并同步移除后的续期域名列表。竞争操作明确提示等待，断开锁持有者后自动释放；不要手工删除锁文件。旧 v1.1.0 EXE 不包含这些修复；使用旧版时不要同时运行两个部署器修改共享代理。

## 常见失败

| 提示 | 处理方式 |
| --- | --- |
| 缺少宿主工具 | 按提示核对具体工具与适用安装命令，再重试；不要因此盲改 DNS |
| DNS 没有指向当前 VPS | 核对全部 A/AAAA，等待解析生效；Cloudflare 暂用“仅 DNS” |
| 80/443 被外部服务占用 | 自行决定如何处理外部服务；TG2Cloud 不会停止它 |
| 证书签发失败 | 检查 80 入站、DNS、Cloudflare 模式和 Let's Encrypt 频率限制 |
| Nginx 自检失败 | 查看部署器脱敏日志；旧域名状态不会被提交覆盖 |
| HTTPS 可用但 `/dav` 返回 403 | 这是预期安全策略，不要把公网域名填进 WebDAV 配置 |
