# 域名访问与 HTTPS

公网管理入口使用 HTTPS；Bot 与网关的传输仍走 Docker 内部 WebDAV。可信内网是独立 HTTP 模式，不要求域名或证书，也不应转发到公网。

## 两种公网代理模式

| 模式 | 适用情况 | 证书与续期 |
| --- | --- | --- |
| managed | TG2Cloud 管理的共享 Nginx / Certbot | 由受管容器检查续期与加载 |
| external_docker | 显式复用符合条件的已有 Docker Nginx | 按已登记的外部证书或 Webroot 方案维护 |

不要停止其他项目的 Nginx / Caddy 来给安装让路，也不要在已有代理前再叠一层抢占 80/443。

## 配置前准备

1. 准备当前 Edition 专用的纯域名，不带协议、端口、路径或通配符。
2. DNS A/AAAA 必须正确指向此主机；无可用 IPv6 时不要填写错误 AAAA。
3. 在云安全组及自行管理的防火墙开放所需 TCP 80/443。脚本不自动放开防火墙。
4. 首次签发时，Cloudflare 使用“仅 DNS”；不向 TG2Cloud 提供 Cloudflare Token。
5. 公网 NAT 主机按提示核对云控制台分配的公网 IPv4、映射及入站条件，不把 A 记录改成私有 IP。

## 在 Linux 中配置

首次公网安装由向导收集域名并配置入口；已安装实例运行 `tg2cloud`，选择对应 Edition，再选 **7. HTTPS 与管理**：

| 子项 | 影响 |
| --- | --- |
| 检查 HTTPS | 检查当前域名、证书、路由和后端，不重新部署 Bot |
| 显式修复 HTTPS | 使用已有域名；需确认，可能短暂影响共享管理入口 |
| 证书续期演练 | 显式 dry-run，需要外网和 ACME，不替换正式证书 |

新域名 / 代理模式变更应按[完整代理指南](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/DOCKER-NGINX.md)核对迁移条件，不能把菜单的“保留已有域名修复”当作任意切换域名的入口。

配置会准备候选路由、检查证书与 Nginx，再做真实本机请求自检。新配置未通过时，不以成功状态覆盖旧路由。中断后重新检查实际状态，不假设网络断开就意味着回退完成。

## 管理域名与外部 WebDAV

管理域名只代理网关后台，公网 `/dav` 与 `/dav/` 被拒绝是预期行为；Bot 继续用自己的内部地址，不把管理域名写入 rclone 配置。

手机读取文件需另装[外部 WebDAV](/deploy/external-webdav/)，使用另一个域名和独立只读账号。外部域名允许专用账号读取 `/dav/`，不能拿管理域名的拦截规则判断外部入口。

公网模式下 CloudDrive2 19798、OpenList 5244 不直接暴露。两个 Edition 需使用不同管理域名；已有模式不会因为重新运行另一入口而自动转换。

## 复用已有 Docker Nginx（v1.4.2）

`external_docker` 会检查容器 / Compose 身份、80/443 真实归属、持久化目录、include、网络和证书责任。多个候选需选择，写入前必须明确授权；面板生成配置、未知归属或挂载不满足要求时停止并给出人工接入计划。

只读检测入口：

```bash
tg2cloud proxy detect
tg2cloud proxy --help
```

只调整受支持的 TG2Cloud 网关网络和专属站点，不停止、重建原代理，不公开网关端口。bridge 使用已声明网络与动态 Docker DNS；不把任意宿主 Nginx 或外部部署当成可自动接管的实例。

有效外部证书保留原维护责任；需要新证书时使用持久 Webroot，不抢占 80/443。宿主自动维护方案要求已存在活动 cron / crond；记录证书变更与实际加载结果，不能把签发成功当成原代理已加载。

共享状态使用 schema 3，旧写入端拒绝操作，不自动降级。模式迁移、逐文件恢复、备份与卸载边界见[仓库专题](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/DOCKER-NGINX.md)。默认 managed 不变，不将隔离测试视为真实 VPS / ACME 已验收。

## 本机自检与公网验收

本机 HTTPS 检查使用真实域名验证证书，通过 VPS 本地路径访问代理，避免公网 NAT 回环限制引起误判。

本机通过后，仍需从另一网络检查：

- HTTPS 管理页与 HTTP 跳转可用；
- 管理域名的 `/dav` 和 `/dav/` 被拒绝；
- VPS 公网 IP 加 19798 / 5244 不能直接打开后台。

外部失败时先看安全组、防火墙、DNS 和代理状态，不关闭 TLS 校验，也不开放后端端口绕过。

## 自动续期与状态记录

managed 模式中，Certbot 容器每 12 小时检查续期，Nginx 容器定期安全加载证书；不靠宿主 cron，不挂 Docker Socket。external_docker 的续期责任单独登记，不套用受管容器规则。

状态区分最近检查、检查成功、证书实际变更与下次检查。检查成功可能只是“尚不需要续签”，不等于产生了新证书。

已有记录超过 26 小时未更新、最近失败、有效期不足 22 天或时钟异常时需排查。完全没有记录不能据此断言续期失败。Let's Encrypt 邮箱不能替代主动查看状态和证书有效期。

旧离线工具需显式升级；仅更新网站或下载脚本不会自动替换实例和续期组件。不要为了增加记录重装 Bot 或删除现有证书。

## 维护工具与续期演练

`tg2cloud` → **7. HTTPS 与管理** 执行显式续期演练；**13. 数据备份管理** 处理共享代理备份、校验、隔离解包和确认清理。

dry-run 不替换正式证书，也不证明长期自动续期已通过。它需要 ACME 网络，可能写测试账户及日志；已有续期配置中的 hooks 仍应事先核对，不是完全只读操作。

演练有超时与精确清理机制。进程被强杀、SSH 中断或 Docker 无响应时，先检查是否仍有活动任务，不假设已经清理或反复启动。

## 更新或移除

路由变更按对应模式的完整命令和计划执行，先备份并核对依赖。保留其他 Edition 和外部 WebDAV 路由；只要还有路由需要共享代理，就不能停掉它。

证书可能被其他入口引用，不应为“重新申请”盲目删除。外部附加功能仍存在时，先处理其依赖，再卸载底层实例。

## 常见失败

| 提示 | 处理方式 |
| --- | --- |
| 缺少宿主工具 | 核对具体工具及适用安装命令，不盲目改 DNS |
| DNS 不匹配 | 核对全部 A/AAAA；NAT 按云控制台核实公网映射 |
| 80/443 被占用 | 检查归属；只在受支持且获授权时复用，不停止未知服务 |
| 签发失败 | 核对入站、DNS、代理方式和签发频率 |
| 本机通过、外网失败 | 检查云安全组、防火墙、DNS 和外部网络 |
| 管理域名 `/dav` 为 403 | 预期拦截，不是 Bot WebDAV 凭据错误 |

按版本区分的实机记录见[验收范围](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/development/DOMAIN-HTTPS-ACCEPTANCE.md)；发布、隔离测试和用户反馈不互相替代。
