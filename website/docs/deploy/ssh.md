# 连接 VPS 与 SSH

部署器通过 SSH 在你控制的 VPS 上执行安装和管理操作。先确认连到正确的服务器，再考虑用户名和密码是否正确。

## 填写连接信息

| 字段 | 说明 |
| --- | --- |
| VPS 地址 | IP 或可解析的域名，不包含 `http://` |
| SSH 端口 | 使用服务商或你自己配置的实际端口 |
| 用户名 | root，或有合适 sudo 权限的普通用户 |
| 登录方式 | 密码，或者 SSH 私钥 |
| 私钥口令 | 仅在私钥本身加密时需要 |
| sudo 密码 | 非免密 sudo 的普通用户需要 |

点击“测试 SSH”，等待结果。先测试成功，再做资源检测和部署。

## 首次连接：核对主机指纹

通过服务商网页控制台或 VNC 登录 VPS，可查看服务器公钥指纹：

```bash
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
sudo ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub -E sha256
```

只核对实际存在且与部署器显示的密钥类型对应的文件。确认控制台指纹和部署器指纹一致后再接受。

## VPS 重装后指纹变化

重新安装系统、恢复快照、重新生成 SSH 主机密钥、IP 被分配给新机器，都可能让指纹变化。但无法解释的变化也可能意味着连错服务器或受到攻击。

新版部署器会显示旧、新密钥类型和 SHA-256 指纹。通过独立控制台核实新指纹后，选择“更新并重新连接”。它只更新当前主机和端口的记录，并重试原操作一次。

:::warning 不要清空所有服务器记录
不应为了省事全局关闭 Host Key 检查或清空 `known_hosts`。无法核实新指纹时选择取消。
:::

当前记录路径是：

```text
%APPDATA%\TG2Cloud-Deployer\known_hosts
```

旧 TG115 的主机记录不会自动导入。更新指纹后仍提示身份认证失败，需单独检查用户名、密码、私钥和口令。

## SSH 隧道与管理页面

CloudDrive2 固定使用本机 19798，OpenList 固定使用本机 5244。管理页按钮会建立隧道并做 HTTP 检查，再打开浏览器。

电脑端口被其他程序占用时，部署器会明确停止，不会随机换端口。关闭部署器后，不要假定隧道仍在；需要时重新打开对应管理页。

更多情况见 [SSH 与管理页问题](/troubleshooting/ssh/)。
