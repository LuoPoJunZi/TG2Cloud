# 连接 VPS 与 SSH

Linux 安装脚本直接在目标主机运行。SSH 只是你登录自己服务器的方式，不再由 TG2Cloud 桌面程序代为连接。

## 从自己的终端连接

例如：

```bash
ssh -p 22 root@你的服务器地址
```

把端口、用户名和地址替换为服务商提供的实际值；上面不是可以原样执行的服务器地址。使用普通账号登录时，确认具备 sudo 权限，再以 root 运行安装脚本。

密码按终端提示输入，不会显示字符。使用私钥时，通过 SSH 客户端选择自己的密钥文件，不要将密码、私钥或口令写进公开命令示例。

## 首次连接：核对主机指纹

通过服务商网页控制台或 VNC 登录 VPS，查看服务器公钥指纹：

```bash
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
sudo ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub -E sha256
```

只核对实际存在且与 SSH 客户端提示相同类型的密钥。确认独立控制台与终端中的 SHA-256 指纹一致后再接受。

## VPS 重装后指纹变化

重装系统、恢复快照、重新生成密钥或地址被分配给新主机都可能导致变化；也可能连错服务器。无法解释时先停止，不能仅因“IP 是自己的”就忽略检查。

核实后，只按所用 SSH 客户端的说明更新这一个主机和端口对应的记录，不清空全部 `known_hosts`，不关闭主机身份校验。身份确认后仍提示认证失败，再检查用户名、密码、私钥或口令。

当前 Linux 脚本没有内置 SSH 客户端或私有主机记录库；记录位置由你使用的 SSH 客户端决定。

## SSH 与管理页面是两条入口

公网实例通过 HTTPS 域名打开 CloudDrive2 / OpenList 管理页，后端 19798 / 5244 不直接公开；可信内网实例使用安装向导显示的私有 IP 地址和固定端口，不启用公网转发。

Linux 脚本不创建桌面 SSH 隧道。不要把 HTTPS 失败当成隧道故障，也不要为解决证书问题开放后端端口。

连接完成后继续[从零开始部署](/guide/quick-start/)。排查见[SSH 与管理页问题](/troubleshooting/ssh/)及[HTTPS 指南](/deploy/domain-https/)。
