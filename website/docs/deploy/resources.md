# VPS 资源与存储预算

任务预算控制 Bot 的本地任务文件额度，不是整台 VPS 的总磁盘限制。

## 两个数字分别控制什么

| 配置 | 作用 | 源码默认 |
| --- | --- | --- |
| `LOCAL_TEMP_BUDGET_GB` | 本地任务可使用的预算 | `20` |
| `MIN_FREE_DISK_GB` | 磁盘至少需要保留的空间 | `8` |

这两个数不是机械相加后就能保证安全。还要考虑已有任务、Docker 镜像、网关缓存、日志、备份、其他服务以及 inode。

资源保护按文件系统区分 Bot 可见目录，不重复叠加同一盘剩余空间；新下载预留前还会重新读取暂存盘可用量。触及安全线时暂停新下载并拒绝新文件，恢复空间后重新采样恢复，用户手动暂停保持不变。容器看不到的独立网关缓存/Docker 数据盘仍需宿主机检查，不承诺自动保护整台 VPS。旧版行为请按对应版本文档核对。

## v1.3.0 脚本资源推荐

v1.3.0 向导为 VPS 和内网首次安装提供流式优先、均衡和手动配置，数值按实际资源计算；手动配置仍需通过检查。升级保留原预算。最终执行前再次读取容量，条件变化时停止。

在线脚本固定到经过 CI 的向导源码，首次交互安装显示推荐选项；手动输入默认 20GB/8GB，仍需通过安全检查。推荐不分区、不扩容，也不限制网关所有缓存。

## 执行前重新检查

安装目录或环境变化后重新探测。首次安装按向导选择推荐值或手动输入，升级保留原预算，执行前再次校验。安装盘和 Docker 数据盘不在同一文件系统时，两边空间都需要合格。旧桌面“检测／应用”按钮不属于 Linux 流程。

## 均衡模式与流式优先

均衡模式给普通下载、完整本地文件和失败保留更多空间。流式优先减少完整落盘额度，更适合磁盘相对紧张的 VPS，但并不消除网关缓存。

例如向导在某台小机器上给出 8GB/8GB 流式优先建议，应先按该实例建议使用，不要未经检测改回 20GB/8GB。

## 为什么有空闲磁盘仍会排队

调度不只看 `df` 的可用空间，还要看已预留额度、运行任务、目的端可达性、资源采样是否新鲜及磁盘安全线。

遇到排队，先看 `/status` 首页、`🖥` VPS 资源和 `/doctor`，不要立即并发启动更多任务。详见 [排队与空间排查](/troubleshooting/transfer/)。

## 查看空间的只读命令

```bash
df -h
df -i
docker system df
```

命令只用于观察。不要把 `docker system prune -a --volumes` 当作通用修复；它可能影响同机其他服务和数据。

:::warning 不会自动替你管理 VPS 磁盘
部署器不会自动分区、格式化、扩容或迁移 Docker 数据目录。CloudDrive2/OpenList 的缓存也不受 Bot 任务预算直接约束。
:::
