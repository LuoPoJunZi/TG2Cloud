# OpenList Edition 部署

按“基础部署 → 挂载存储 → 创建 WebDAV 用户 → 验收”的顺序操作。OpenList 管理员账号与 Bot 专用 WebDAV 用户是两套用途不同的账号。

## 一、下载、连接与资源检查

下载 `TG2Cloud-OpenList-Deployer.exe`，填写 VPS 和 Telegram 配置，点击“测试 SSH”，核对主机指纹，应用适合当前实例的存储建议。

默认安装目录是 `/opt/tg2cloud-openlist`。本地任务预算与磁盘保留默认分别为 20GB、8GB，但应以资源检测结果为准。

## 二、记录首次管理员凭据

“部署 OpenList”页面会生成首次管理员密码。它只用于 **全新 OpenList 数据目录的初始化**。

已有实例再次部署不会自动重置管理员密码；部署器识别到已有实例后，会提示使用原凭据，并隐藏不适用的首次密码区域。

:::warning 不要把“重新生成”当成修改服务端密码
关闭部署器后，本次在本地生成的密码不会保存。请在你自己的密码管理器中妥善保管；重新生成表单值，不会自动更改已有 OpenList 服务端账号。
:::

## 三、部署基础环境

点击“一键部署基础环境”。这个阶段只要求 Bot、OpenList 和内部网络健康；未添加云盘或尚未创建 WebDAV 用户是首次安装的正常中间状态。

等待明确成功后，再打开管理页。不要为了通过基础部署而随意修改数据库或重置旧管理员。

## 四、挂载自己的云存储

点击“打开 OpenList 管理页”，通过固定 SSH 隧道访问：

```text
http://127.0.0.1:5244
```

登录 OpenList，在自己的后台添加并授权存储，例如项目验收使用的 `115 Open`。授权方式和所需字段依驱动而定，请以当前驱动文档为准。

Cookie、OAuth Token、刷新令牌和云盘密码只应交给你自己的网关，不要填写到 TG2Cloud 文档站，也不要发给维护者。

## 五、创建 Bot 专用 WebDAV 用户

按照部署器“配置 WebDAV”页的值，在 OpenList 中创建专用普通用户。新装建议用户名为 `tg2cloud`，密码由部署器本地生成，可复制。

配置该用户基本路径为希望写入的实际目录，授予目录列表、读取、创建/写入、删除能力。不同 OpenList 版本的权限名称可能不同，应以真实验收为准。

受管 OpenList 的内网 WebDAV 地址为：

```text
http://tg2cloud-openlist:5244/dav/
```

目标子目录默认留空，表示直接写到专用用户的 WebDAV 根目录。需要更下一层时，可填 `Telegram` 或 `Media/Telegram` 等相对路径，不要重复用户基本路径。

## 六、分阶段验收

点击“WebDAV 验收”，检查 Bot、OpenList 服务、认证、目标目录、写入、大小、最终落盘和清理阶段。

```text
TG2CLOUD_DESTINATION=OK
```

只有总体成功标记出现，才认为当前配置满足 TG2Cloud 所需的 WebDAV 能力。某阶段失败后，后续“未执行”不是“通过”。

:::info v1.0.2 的关键差别
部分 OpenList/115 Open 挂载可能在 MOVE 返回成功后仍未生成目标文件。当前 OpenList Edition 预留无冲突最终路径后直接写入，不依赖 WebDAV MOVE；不要照搬 CloudDrive2 的改名排错流程。
:::

## 七、日常管理与已有实例

右侧日常管理区提供状态、最近脱敏日志、分别重启 Bot/OpenList、安全备份和管理员密码恢复。

安全备份会短暂停止两个服务以保证一致性；管理员密码恢复需要两次确认，会影响现有登录。不要把它当作普通排错按钮随手点击。

重复部署默认保留 VPS 当前 `.env`。只有明确选择覆盖配置，才应用本次表单；保留旧 WebDAV/管理员配置的选项，应按界面说明慎重使用。
