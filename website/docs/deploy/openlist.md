# OpenList Edition 部署

按“基础部署 → 挂载存储 → 创建专用 WebDAV 用户 → 写入验收 → 小文件转存”的顺序操作。管理员账号和 Bot 的 WebDAV 账号用途不同。

## 一、安装与资源检查

按[从零开始部署](/guide/quick-start/)在自己的 Linux 主机运行公网或内网入口，选择 **2. OpenList**。支持符合部署要求的 Linux（Debian / Ubuntu），标准安装目录为 `/opt/tg2cloud-openlist`，产品配置不要求 FUSE。

首次安装按资源推荐选择预算和保留线，不机械套用源码的 20GB / 8GB 默认值。填写 Telegram 管理员 ID 和专用 WebDAV 凭据，核对计划后执行；直接在 Linux 终端完成。

## 二、记录首次管理员凭据

全新 OpenList 数据目录的初始化管理员密码由向导生成，在自己的私有终端按提示查看和保存。Bot 专用 WebDAV 密码是另一项凭据，不能混用。

已有实例保留服务端原管理员密码，不自动重置。安装后可从 `tg2cloud` → **6. WebDAV 凭据** 逐项确认查看已保存信息；保存的初始化密码可能已被你在后台更改，不能保证仍可登录。

不要把重新运行安装或生成新表单密码当成修改服务端管理员密码的方法。

## 三、部署基础环境

等待 Bot、OpenList 和内部网络健康，再核对管理入口。尚未挂载云存储或创建 WebDAV 用户，是首次安装的正常中间阶段，不代表应删除数据库重装。

公网通过 HTTPS 域名管理；可信内网通过向导显示的 `http://内网IP:5244` 管理。公网 5244 不直接开放，HTTPS 与已有代理接入见[入口指南](/deploy/domain-https/)。

## 四、挂载自己的云存储

登录自己的 OpenList 后台，添加并授权目标存储，例如 `115 Open`。授权方式随存储驱动不同，请核对所用网关与驱动的实际要求。

Cookie、OAuth Token、刷新令牌和云盘密码只交给你自己的网关，不向文档站或维护者提供。

## 五、创建 Bot 专用 WebDAV 用户

创建普通用户，用户名和密码与安装时保存的值一致，新装默认用户名为 `tg2cloud`。

把基本路径限定为实际保存目录，授予目录列表、读取、创建 / 写入和删除能力；不直接用管理员替代。权限名称随网关版本不同，应以真实操作能力为准。

Bot 的内部地址由受管部署配置：

```text
http://tg2cloud-openlist:5244/dav/
```

Bot 保存子目录默认可留空，直接使用该用户根目录；需要更下一层时填写 `Telegram` 等相对路径。不要把基本路径再重复填写一次，也不要把管理域名换进 Bot WebDAV 配置。

## 六、分阶段验收

运行 `tg2cloud`，选 OpenList，再选 **11. WebDAV 验收**。确认后才创建并清理随机小测试文件，核对认证、目录、写入、大小复验和清理：

```text
TG2CLOUD_DESTINATION=OK
```

只见“认证通过”或容器 healthy 不能替代这个标记。OpenList 预留无冲突最终路径后直接写入，不依赖 MOVE；`TG2CLOUD_WEBDAV_MOVE=NOT_REQUIRED` 不是漏检。

失败后先修复第一处错误，不连续重试放大 401 / 429。详见[WebDAV 排查](/troubleshooting/webdav/)。

## 七、日常管理与已有实例

运行 `tg2cloud`，通过 **2. 查看运行状态**、**3. 查看运行日志**、**4. 服务启停管理** 选择操作。重启网关会影响存储访问，不要把它当作普通刷新。

**13. 数据备份管理** 支持实例快照、共享代理备份和隔离预检；两者范围不同，不包含云端文件，也不提供覆盖生产数据的一键恢复。详见[备份说明](/operations/backup/)。

升级默认保留已有配置和管理员信息，不能靠重复升级应用一组新密码。显式变更见[升级与配置](/operations/update/)；完成后发送[第一个小文件](/usage/first-transfer/)验证。
