Edition、实际版本、运行状态和安装目录从所选实例读取，不固定示例值。所选 Edition 未安装时，先确认是否进入安装向导；不会因选择 OpenList 就操作 CloudDrive2。

```bash
tg2cloud
tg2cloud manage --edition clouddrive2
```

从已审阅的本地源码运行可使用：

```bash
python3 /path/to/TG2Cloud/scripts/run_source.py manage
```

状态与日志不下载新代码；**1. 安装与升级** 核对主实例正式稳定 Release，外部 WebDAV 首次取用与显式升级也只下载校验后的稳定源码。已有公网 / 内网模式保留，不因入口名称不同而转换。

**16. 监听管理从 v1.4.10 提供**：登录、查看状态、停用监听在子菜单完成，沿用所选 Edition 与安装目录。正式 v1.4.9 仍使用 listen 子命令；手机号／验证码可见、仅两步验证密码隐藏的调整从 v1.4.10 提供。

## 查看实际运行版本与日志

v1.4.5 的 2／3／10 页面可停留、刷新和明确返回；1 重新检查／读取，0 或回车返回主菜单。状态用中文分项，停止容器不复用旧健康成功；日志按服务分组，单源失败不遮住另一源。其余次级页面统一标题与对象，通知参数逐行显示，诊断终端与 Markdown 导出分开渲染；原确认与权限不变。旧离线工具需显式升级，按本页当前菜单操作。

**2. 查看运行状态** 核对所选实例；不能把下载脚本显示的目标版本当成失败后实际运行版本。

**3. 查看运行日志** 读取近期脱敏结果。分享前仍需自己检查个人信息，不上传原始配置、数据库、备份或 Session。

两个 Edition 的底层只读命令仍有效：

```bash
sudo /opt/tg2cloud-clouddrive2/manage.sh status
sudo /opt/tg2cloud-clouddrive2/manage.sh logs
sudo /opt/tg2cloud-clouddrive2/manage.sh check
```

OpenList 将目录换为 `/opt/tg2cloud-openlist`。不要用另一 Edition 的路径处理当前实例。

## 服务启停

**4. 服务启停管理** 直接列出启动、停止、重启 Bot 或网关的六个动作；只操作选定容器，需确认。网关重启可能影响管理和外部读取，Bot 重启可能中断任务。

底层脚本存在差异：CloudDrive2 的 `manage.sh restart` 只重启 Bot；OpenList 的同名命令会重启网关和 Bot，只重启它的 Bot 应使用 `restart-bot`。优先通过菜单明确选择对象。

重启不安装新版本，也不等于应用新配置，详见[升级与配置](/operations/update/)。

## 用户、凭据与可选设置

| 主菜单 | 用途与边界 |
| --- | --- |
| 5. Bot 用户管理 | 添加、停用或移除可信家人；查看、设置或取消成员配额，不创建个人目录 |
| 6. WebDAV 凭据 | 每项在私有终端确认后显示保存值；不改密或重置管理员 |
| 8. 文件分类设置 | 直接选择不分类、类型、年份、年月或类型与年月，仅影响新任务 |
| 9. 异常通知设置 | 总开关、恢复通知与磁盘阈值，默认关闭，仅通知管理员 |

设置保留锁和 revision 校验，不要求重启 Bot。磁盘提醒阈值 0 跟随原安全线，不用通知设置降低保护。家人的 Bot 授权与[外部 WebDAV 只读账号](/deploy/external-webdav/)分别管理。

**15. 外部 WebDAV** 直接沿用当前 Edition 与核验后的实际安装目录，打开安装、检查、启停、配置、升级、卸载和用户管理子菜单；无需额外安装命令。首次尚无工具时先确认，再下载校验正式稳定源码，打开向导不等于启用入口；已有工具核验归属和完整性后离线启动。主安装向导仍不询问或默认启用，不修改 Bot 凭据、目录和数据库，不重启 Bot／网关。子菜单选择 0 返回主菜单，历史独立入口保留兼容，详见[统一管理说明](/deploy/external-webdav/#统一管理)。

分类不移动历史文件或修改旧任务目录；通知在 Bot 停止或完全断网时不能保证送达。详细规则见[可选功能说明](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/FEATURE-ENHANCEMENTS.md)。

## 两种健康检查的区别

| 操作 | 含义 | 真写目标 |
| --- | --- | --- |
| 10. 业务就绪检查 | 读取最近 Telegram、目的端、调度和容量观察；过期显示未核实 | 否 |
| Bot `/doctor`、`manage.sh check` | 诊断 / 基础配置与运行检查，不等于写入能力通过 | 否 |
| 11. WebDAV 验收 | 确认后创建、上传、大小复验并清理随机测试文件 | 是 |

就绪检查不追加网络探测、不绕过 OpenList 冷却、不自动重启。healthy、最近就绪与 `TG2CLOUD_DESTINATION=OK` 是不同层面的证据。完整流程见[真实验收](/deploy/verification/)。

`tg2cloud naming-preview` 仍可独立使用，但不再列在主菜单；Bot 自动命名不受影响。规则与限制见[命名指南](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/NAMING.md)。

## OpenList 认证与限流诊断

Bot `/doctor` 显示最近实际探测时间、错误分类和剩余冷却，不把消息刷新时间当成重新检测成功。

| 结果 | 只读探测保护 | 处理 |
| --- | --- | --- |
| 401 | 冷却 5 分钟 | 核对网关专用用户与实际运行配置 |
| 429 | 60、120、240、480、900 秒逐步退避 | 停止高频重试，查看上游与网关限制 |

刷新不绕过冷却；冷却结束不保证服务端已解除限制。显式写入验收是另一项会创建文件的操作，不反复运行来绕过保护。详见[WebDAV 排查](/troubleshooting/webdav/)。

## HTTPS、备份与诊断报告

**7. HTTPS 与管理** 检查 / 修复当前入口，或显式执行续期 dry-run。内网实例保留原 HTTP 模式，不隐式申请证书。

**12. 故障诊断报告** 只读汇总白名单版本、资源、状态和最近失败分类；未知项显示“未检查”，不读取原始聊天、文件名或完整凭据。先展示，确认后在本机私密保存，不自动上传。

v1.4.5 诊断补充只读入口结果及认证、权限、冷却、容量和远端冲突的处理建议；不自动修复或重启，历史失败分类不等于当前故障。旧 v1.4.4 工具需升级，见[维护说明](https://github.com/LuoPoJunZi/TG2Cloud/blob/c7e0b4b7497fbfa258c752dcff4666d1e2011eae/docs/development/MAINTENANCE-NEXT.md)。

**13. 数据备份管理** 分别处理实例回退点、实例快照与共享代理备份；快照有服务暂停影响，隔离预检不等于生产恢复。完整范围见[备份说明](/operations/backup/)。

安装 / 升级日志分级及验收摘要见[升级反馈](/operations/update/#安装与升级反馈)，不把摘要中未执行项标为通过。

## 卸载当前实例

**14. 卸载当前实例** 只处理所选 Edition，需再次核对完整计划与删除确认，不删除云端文件或另一 Edition 的业务数据。附加入口仍依赖网关时先处理依赖，仅 disable 不等于解除依赖。

最后一套完整卸载后，只有无保留实例、数据 / 备份或附加依赖且归属可核验，才删除 `tg2cloud` 与受管代码。系统 Docker / Nginx、镜像缓存、锁元数据等不承诺恢复原状。

卸载不是升级步骤；保留数据需使用相应保留模式，见[卸载指南](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/UNINSTALL.md)。

## 提交问题前

记录 Edition、实际版本、操作阶段和第一处错误，先自行脱敏。不要公开 `.env`、rclone 配置、数据库、Session 或备份，详见[安全说明](/reference/security/)。

## v1.5.0：Bot 与管理工具版本核对

v1.5.0 将 Bot 和宿主 CLI 分开核验：离线工具来自目标正式 Release 的已校验源码，安装提示包含实际 CLI 版本、目标是否一致以及离线命令检查。管理首页显示当前进程版本；工具更新后需退出旧菜单，再运行 `tg2cloud`。

从 v1.4.11 或更早版本首次升级时，使用[下载页](/download/)中的公网或内网在线入口；旧管理进程不会自行加载新版工具更新逻辑。

升级后可用 `tg2cloud --version` 查看 CLI，`tg2cloud listen --help` 检查监听入口；这些命令不执行 Telegram 登录。Bot 的运行代码／版本和 CLI 的可用性分别判定，缺少证据时明确未核实。监听登录兼容在线向导标准输入被重定向的控制终端，2FA 继续隐藏。

用户已提供两台 Linux 的 v1.4.11 基础升级记录，Bot、备份和本机 HTTPS 通过，但 CLI 版本未单独核验、监听登录未完成。真实转存等范围见[实机补充](https://github.com/LuoPoJunZi/TG2Cloud/blob/c7e0b4b7497fbfa258c752dcff4666d1e2011eae/docs/development/V1411-ACCEPTANCE.md)，本版修复的实机验收尚未执行。
