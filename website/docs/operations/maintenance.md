# 状态、日志与重启

## 主动通知与诊断报告（v1.4.3）

v1.4.3 新增 `tg2cloud` 菜单 13“故障诊断报告”、14“分类／异常通知设置”；须同时升级 Bot 和离线管理工具。

主动通知默认关闭，仅给唯一管理员发送固定中文信息，不向家人公开系统详情。磁盘提醒0跟随原安全线，不能降低保护；支持恢复通知开关。同类故障冷却30分钟，WebDAV持续异常观察5分钟，资源等待观察30分钟。故障/发送状态持久化，不追加探测，不绕过401/403/429冷却。过期样本不宣称恢复；Bot退出、容器停止或完全断网时不能保证送达，不新增宿主监控守护进程。

报告只读整合白名单版本、Edition、架构、Docker/Compose、空间/预算与最近7天当前失败任务分类。不读取原始日志、聊天、文件名、完整路径或凭据。先展示，确认后本机私密保存，文件0600，不自动上传。不重启、不安装、不写WebDAV；未知项目写“未检查”，HTTPS/LAN用原菜单6单独核验。

先用只读检查定位问题，再决定是否重启或执行会写文件的验收。路径要与安装的 Edition 一致。

## 本地管理菜单

v1.4.4 的日志分类与升级验收汇总只补充执行反馈，不再次调整下方已确认的菜单。详细的分类、证据边界与示例见[升级反馈](/operations/update/#v1-4-4-安装与升级反馈)；已有正式工具须后续更新才生效，不把 healthy 当成真实转存通过。

版本、Edition、Bot 状态和安装目录由实例实际读取，此处不固定示例值。文件分类直接提供不分类、类型、年份、年月和类型与年月五种选择，只影响新任务，不改文件名或整理历史文件。异常通知直接提供总开关、恢复通知与磁盘阈值；只通知管理员，恢复通知须总开关开启，阈值 0 跟随原安全线。确认后保存、保留锁和 revision 校验，无需重启 Bot。

v1.4.3在保留原菜单序号的基础上增加 **11. 业务就绪检查**、**12. 命名预览（不转存）**；须升级离线管理工具和 Bot。就绪检查只读最近的连接、目的端、调度与容量观察，不发起额外网络请求，不绕过 OpenList 冷却，不改变 Bot 首页或自动重启策略。观察过期／旧 Bot 无协议时显示未核实，不把 healthy 当作实际转存完成。源码用法见[维护增强说明](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/development/MAINTENANCE-IMPROVEMENTS.md)。

v1.3.2 默认安装向导在确认计划后安装离线 `tg2cloud` 命令；先选择 CloudDrive2／OpenList，再使用编号菜单：安装升级、状态、日志、启停、WebDAV 验收、HTTPS／入口、备份、凭据、卸载，以及 0 退出。状态与日志不下载代码；安装升级仍只选正式稳定 Release。旧主机需重新运行对应向导并确认更新，同版本可仅安装管理命令而不重启容器；不是自动更新。

公网／内网安装命令不带参数时共用此入口：所选 Edition 未安装就确认进入对应向导，已有实例就显示管理菜单。新安装使用入口对应的公网／内网模式；已有模式不因入口变化而改变。比如选择 `2. OpenList` 而尚未安装时，会进入 OpenList 安装引导，不会把它当作“运行状态”。日常无需单独记卸载命令，旧 `uninstall.sh` 仍作兼容／救援入口。

```bash
tg2cloud
tg2cloud manage --edition clouddrive2
# 从已审阅的源码本地运行（不依赖当前目录）：
python3 /path/to/TG2Cloud/scripts/run_source.py manage
```

正式 v1.4.3 的启停先选 Bot 或网关；v1.4.4 菜单直接列出六个动作、回车默认返回，两者都只操作显式选定的一个容器并要求确认。验收会真写并清理随机测试文件，单独确认，不自动反复重试。HTTPS 修复沿用已有域名，续期 dry-run 另行确认；LAN 实例保留原内网模式，不隐式申请证书。查看凭据每项私有终端确认，不进日志。卸载复用原有归属、附加功能依赖保护和删除确认，自定义目录不自动卸载。

备份菜单可查看实例升级回退点，以及创建／查看／隔离校验最近共享代理备份；代理清理先预览、再确认，固定保留最近 5 份有效备份。不提供覆盖生产数据的自动恢复。离线代码只包含管理源码与版本／哈希清单，保存在私密 `/opt/tg2cloud-cli/runtime/`，不复制 Bot 配置、Session 或数据库，不覆盖未知同名命令。

“卸载当前实例”在正式 v1.4.3 为 9，v1.4.4 菜单为 14，仅作用于当前所选 Edition。卸载 CloudDrive2 不删除或重启 OpenList 的 Bot/网关，也不清理其数据或域名；共享代理路由更新可能短暂重载。最后一套默认完整卸载后，若无其他实例、保留数据/备份、附加路由或挂载依赖，才核验并删除 `tg2cloud` 与全部受管管理代码，然后退出菜单。未知资源、忙碌和保留数据模式不强删。系统 Docker/Nginx、云端文件、镜像缓存与锁元数据仍保留，不能承诺系统逐字节恢复原状。详细限制见[仓库运维文档](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/OPERATIONS.md#本地管理菜单)。

以下弹窗与桌面按钮属于历史 v1.2.1，不是新的 Linux 菜单；原每实例 `manage.sh` 继续有效。

## 查看实际运行版本

从 v1.1.2 起，部署器“查看运行状态”的结果弹窗与运行日志分别显示本机部署器版本和 VPS Bot 实际版本。VPS 版本来自正在运行的 Bot，不用本机 EXE 版本代替；未安装、已停止或旧 Bot 无法报告版本时明确显示未安装或未获取。

下载新 EXE 不等于 VPS 已升级，也不会自动降级较新的 Bot。需要升级时按 [升级与修改配置](/operations/update/) 保留配置重新部署；容器健康不等于 WebDAV 写入通过。

## 部署阶段与失败提示

既有进度区域与运行日志显示实际 SSH、基础环境、资源上传、运行环境、存储服务、Bot 和健康检查阶段；HTTPS 另有环境、ACME 引导、证书与最终自检阶段，不使用猜测的百分比。

失败弹窗给出当时阶段、已有错误详情和核对建议。阶段不是根因；日志未确认时，不直接断言 DNS、证书或凭据错误。查看完整日志后再决定重试，不为排错自动重装、删除数据或停止未知服务。

## CloudDrive2 常用命令

```bash
sudo /opt/tg2cloud-clouddrive2/manage.sh status
sudo /opt/tg2cloud-clouddrive2/manage.sh logs
sudo /opt/tg2cloud-clouddrive2/manage.sh check
```

`status` 查看状态，`logs` 查看近期 Bot 日志，`check` 核对配置、代码指纹和基础心跳。输出可能含个人信息，分享前仍需自行审查脱敏。

## OpenList 常用命令

```bash
sudo /opt/tg2cloud-openlist/manage.sh status
sudo /opt/tg2cloud-openlist/manage.sh logs
sudo /opt/tg2cloud-openlist/manage.sh check
```

部署器的 OpenList 日常管理区也提供状态、脱敏日志和分别重启服务的操作。不要用另一 Edition 的路径处理当前实例。

## 重启 Bot

```bash
sudo /opt/tg2cloud-clouddrive2/manage.sh restart
```

CloudDrive2 此命令只重启 Bot。OpenList 的 `manage.sh restart` 会同时重启网关与 Bot；只重启其 Bot 应用 `restart-bot`，或使用 `tg2cloud` 的服务控制菜单明确选择对象。普通重启不重新创建容器环境，配置应用另看[配置修改](/operations/update/)。

停止或启动时使用对应脚本的 `stop`、`start`；会影响服务可用性，操作前留意当前任务。

## 两种健康检查的区别

| 操作 | 是否真写目标文件 |
| --- | --- |
| Bot `/doctor` | 否，面向只读诊断 |
| `manage.sh check` | 不用于真写验收 |
| `manage.sh verify` | 是，会上传并删除小测试文件 |

不要把 `/doctor` 通过当作写权限已经验收。完整步骤见 [WebDAV 验收](/deploy/verification/)。

## OpenList 认证与限流诊断

当前 Bot `/doctor` 保留最近实际探测时间、401／429 分类和下一次允许探测的剩余时间，状态首页仍保持简洁。

| 结果 | 只读探测策略 | 应如何处理 |
| --- | --- | --- |
| HTTP 401 | 冷却 5 分钟 | 核对网关用户与 VPS 当前 WebDAV 配置 |
| HTTP 429 | 按 60、120、240、480、900 秒退避，最长 15 分钟 | 停止重复验收，检查网关日志与上游限流 |

刷新消息不会绕过冷却，也不会把刷新时间写成真实探测时间。冷却结束只表示客户端允许再检查，不保证服务端解除限流；部署器显式 WebDAV 写入验收仍是独立流程，不复用只读缓存。详见 [WebDAV 错误排查](/troubleshooting/webdav/)。

## HTTPS 维护入口

Linux 使用 `tg2cloud` 的 HTTPS 管理入口检查／修复 HTTPS 和执行当前域名续期 dry-run，使用备份管理创建、列出、校验／隔离解包最近代理备份以及确认清理。正式 v1.4.3 为菜单 6／7，v1.4.4 菜单为 7／13，按实际菜单名称定位。共享代理备份不包含业务 DB 或云端文件；实例快照是备份子菜单的另一项显式操作。它们不升级 Bot；旧“维护工具”按钮属于历史 Windows 界面。

操作范围、执行时限与警告见 [域名访问与 HTTPS](/deploy/domain-https/)；敏感备份与删除边界见 [备份与恢复](/operations/backup/)。不要把维护工具当作在线覆盖恢复。

## 发现旧 TG115

当前 CLI 发现对应旧 TG115 而无完整 TG2Cloud 时停止，不按早期桌面“只提示继续”的规则接管。维护仅面向已核验的本 Edition，不替你迁移或删除旧实例。

记录 Edition、版本、最后一次成功操作、第一处错误和是否刚改过配置。提供经过自己复核的脱敏日志，而不是完整 `.env`、数据库或备份。见 [安全说明](/reference/security/)。
