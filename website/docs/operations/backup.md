# 备份与恢复边界

先明确哪些数据被包含，哪些没有被包含。备份包本身可能含敏感凭据，不能公开上传。

## CloudDrive2 Edition

当前没有手动业务“创建安全备份”UI；HTTPS 维护菜单的共享代理备份是另一种范围。重新部署前的内部备份包含程序和配置、现有 `rclone.conf`，并在可用时创建 SQLite 一致性快照。

它**不包括**下载目录、日志以及 CloudDrive2 状态目录；也不备份云端实际文件。需要完整灾难恢复时，应另行保护这些必要数据，不能只保留升级回退点。

## OpenList Edition

日常管理中的安全备份包含程序配置（含 `.env`、`rclone.conf`）、可用的 SQLite 快照及已初始化的 OpenList 状态，排除网关临时文件与日志。

为了避免复制不一致的 OpenList 数据，操作会短暂停止 Bot 和 OpenList，结束后重新启动并检查健康。它也不包含下载文件、TG2Cloud 日志或云端文件。

## 共享 HTTPS 代理需要独立备份

两个 Edition 的现有备份都**不包含** `/opt/tg2cloud-proxy`。强制 HTTPS 之后，仅恢复 Edition 数据仍不足以恢复管理入口。

当前 v1.1.3 源码可在任一 Edition 的“HTTPS 管理入口 → 维护工具”中选择“备份共享代理”，保存以下内容：

- `state/domains.json`：两个 Edition 的域名与后端端口映射；
- `docker-compose.yml`、`nginx/nginx.conf` 和 `nginx/conf.d/`：共享代理与续期配置；
- `certbot/letsencrypt/` 完整目录：包括 `live/`、`archive/`、`renewal/` 和账户信息，保留符号链接及其目标，不能只复制 `live/` 下的链接；
- 每域名续期记录：区分检查成功与证书文件实际变更。

维护工具使用同一 VPS 事务锁，不需要手动停止 Certbot 或 Bot。若自动续期同时改变源文件，工具拒绝不一致快照并移除本次未完成归档，稍后再试。代理备份不包含业务数据库、下载文件、云端文件、运行日志或 ACME 临时 challenge；如果还要备份 Edition 数据，应遵循其独立一致性要求。

归档与校验文件只留在 VPS `/opt/tg2cloud-proxy-backups/`，目录权限 700、文件权限 600，不回传本机。私钥与 ACME 账户数据不能上传 GitHub、公开网盘或工单；需要离机副本时，自行使用安全传输并考虑加密。

“核验最近代理备份”检查归档 SHA256、内部清单及各文件校验。“隔离恢复演练”解包到新建私密测试目录，核对内容和权限后清理，不覆盖在线配置、不启动服务或替换证书；**隔离解包通过不等于灾难恢复后的服务启动验收**。

备份相关操作远端执行上限为 150 秒，退出与清理还需额外时间。中断信号会触发本次未完成归档或隔离目录清理；SSH 不可达时不能保证立即清理成功，恢复连接后先检查。工具不会自动删除历史归档，也不会停止运行中的 Bot。

## 代理历史备份与清理预览

在“维护工具 → 管理历史代理备份”查看时间、大小和完整性，并选择历史归档进行核验或隔离解包。

1. 设置保留最新份数，默认 5 份，可选择 1～50 份。
2. 点击“预览清理”，只列出拟删除归档、对应校验文件和空间，不执行删除。
3. 核对保留备份与清单后，再点击“执行清理”；二次确认默认取消。

清理要求所有候选备份校验通过，并至少保留一份有效备份。新增/修改备份或改变保留数量后，必须重新预览；工具只删除确认清单中的归档及校验文件，不递归清空目录，也不处理无关文件。

:::danger 代理备份删除不可撤销
先确认有独立可恢复副本。删除失败或中断可能已经完成部分清理，应刷新清单核对，不要假设自动回滚。正式版本的实机记录仅验证无删除预览，没有删除真实历史备份。
:::

## 完整代理恢复仍需独立演练

恢复时先在隔离环境检查归档、权限、状态版本和域名映射，再确认 80/443 归属及两个后端仍只监听回环地址。复用有效证书，依次验证 Nginx 配置、本机 HTTPS、外部网络访问和续期。不要将整包直接解压覆盖生产 `/opt`，也不要删除现有证书强迫重新签发。当前没有一键代理 Restore，完整恢复仍需要管理员独立演练。

## 默认备份目录

```text
/opt/tg2cloud-clouddrive2-backups
/opt/tg2cloud-openlist-backups
/opt/tg2cloud-proxy-backups
```

前两个是 Edition 业务备份，第三个是共享代理备份。下面的 Edition 命令只查看各自业务备份的数量与占用；代理历史清单使用 HTTPS 维护工具：

```bash
sudo /opt/tg2cloud-clouddrive2/manage.sh backups
sudo /opt/tg2cloud-openlist/manage.sh backups
```

部署会报告备份占用，超过 5GB 时提示人工关注，不在升级时自动清空历史回退点。

## 显式删除 Edition 旧回退点

下面的命令会删除符合脚本规则的旧备份，每类保留最新 5 份：

```bash
sudo /opt/tg2cloud-clouddrive2/manage.sh prune-backups 5
```

:::danger 删除前先确认
第一次升级后的真实文件验证完成前，不要急着运行清理。`prune-backups` 是有破坏性的保留策略，不是查看命令。确认 Edition、备份可用性和保留数量后再执行。
:::

脚本只处理当前 Edition 备份目录内特定命名的普通文件，不清理旧 TG115 或共享代理备份，也没有代理清理菜单的预览步骤。不要把这个范围扩大为手动递归删除整个 `/opt`。

## 恢复不是一键承诺

v1.1.3 没有正式自动 Restore。旧 TG115 的队列/数据库迁移也未被声明完成真实环境验收。

备份可读取不等于恢复已验证。重要部署应在受控环境制定恢复步骤，并保留独立可恢复副本；不要边猜数据库位置边覆盖生产实例。

## 私密保存

备份含 Token、密码和网关状态。放在自己控制的受限目录，传出 VPS 时使用安全传输并考虑加密，不要把完整包附到公开 Issue。
