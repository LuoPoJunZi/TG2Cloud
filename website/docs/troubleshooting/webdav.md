# WebDAV 错误排查

优先看验收的第一处失败阶段。认证、路径、权限、限流和后端落盘问题需要分开处理。

## 401 Unauthorized：先核对运行凭据

检查网关专用 WebDAV 用户名和密码是否与 Bot **当前运行配置**一致，不是只看 Windows 表单。

既有 TG2Cloud 重复部署默认保留 VPS `.env`。表单改了但没选择应用，或者只执行 `restart`，旧配置仍可能继续使用。

明确 [应用配置](/operations/update/) 后，运行 `check` 与 `verify` 验证，不根据历史日志判断新状态。

## 429 Too Many Requests：避免加压

这是限流信号。暂停高频验收或批量重试，遵循服务端返回的等待提示；不要反复生成新用户、改密码或增加并发试图绕过。

没有适用于所有服务的固定等待秒数。限流解除后，用一个小测试恢复验证。

v1.1.1 为 OpenList 只读健康探测增加保护：成功结果短时间复用；HTTP 429 从 60 秒开始退避，连续限流最多延长至 15 分钟；HTTP 401 冷却 5 分钟。Bot 状态按钮刷新不会绕过冷却。这个间隔是客户端保护策略，不是服务端保证的解封时间，也不会限制你在部署器中显式执行的写入验收。

从 v1.1.2 起，OpenList Bot `/doctor` 增加最近实际探测时间、401/429 分类和剩余冷却显示。冷却期间刷新只更新诊断消息，不发起新的探测；不能把消息时间当作刚刚验证成功。剩余时间归零也不保证服务端已经解封。

旧 v1.1.0 EXE／旧 VPS payload 不包含这项修复。下载新版 EXE 不会自动更新 VPS Bot，需备份后明确部署新版 payload；不能据此认为旧实例已经停止重复探测。本轮限流保护通过自动回归，尚未重新完成真实 OpenList Bot 的 401/429 恢复验收。

## 目录不存在或目标位置不对

先用 WebDAV 专用用户确认其根目录，而不是用管理员视角猜路径。

检查是否把用户基本路径又重复写进部署器子目录。子目录通常使用相对路径；如果根目录已是目标文件夹，就留空。

示例与规则见 [CloudDrive2 配置](/deploy/clouddrive2/) 和 [OpenList 配置](/deploy/openlist/)。

## 可以列目录，但不能上传或删除

列目录权限不等于写权限。确认 CloudDrive2 用户不是只读，并能写入、改名、删除；OpenList 至少应能列表、读取、写入与删除。

底层云存储配额、挂载失效和驱动写入限制，也可能使权限看似开启但操作失败。以真实验收结果为准。

## CloudDrive2 改名或复验失败

当前 CloudDrive2 使用临时文件上传后改名并复验。检查改名权限、目标路径冲突、网关挂载和后端状态。不要看到 HTTP 成功就跳过正式文件复验。

## OpenList MOVE 问题

v1.0.2 针对部分 OpenList/115 Open 的 MOVE “返回成功但文件未生成”改为预留最终路径直接写入。

因此遇到旧教程要求“修复 MOVE 才能上传”，先核对当前 Edition 与版本，不要为了追随旧流程破坏现有配置。

## 连接失败或 Docker 主机名无法解析

同机受管网关地址是 Docker 内网地址。Bot 容器必须位于正确网络，网关容器必须可用。

CloudDrive2 的网络修复按钮只在此类问题且符合部署器提示时使用。它不会修复 401、429、只读账号或云盘空间不足。

## 清理失败

验收包含删除测试文件，不能忽略最后的清理错误。检查删除权限并保留现场，不要用手动递归删除整个网盘目录来“清干净”。

最终通过标记应为 `TG2CLOUD_DESTINATION=OK`。只读问题诊断使用 `/doctor`，真实写入验证使用 `verify`。
