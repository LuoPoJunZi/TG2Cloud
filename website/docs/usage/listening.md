# 管理员监听与转存计划

本页对应正式版 v1.4.9；需显式升级 Bot 与离线工具后使用，旧版本不包含这些功能。真实 Telegram 登录、两网关转存和 VPS 恢复安排在发布后验收，自动化通过不替代实机结论。

## 先了解边界

监听是可选的个人 Telegram 账号组件，默认关闭；现有 Bot 私聊发送／转发文件仍自动转存。普通家庭成员看不到监听管理，也不能通过命令、按钮、交互文本或任务编号使用监听身份。安装仍只填写一个管理员 ID，没有增加必填环境变量、网站、端口、代理或运行依赖。

只处理个人账号已经加入且有权访问的频道／群组。受保护或无法确认保护状态的来源／消息跳过，不自动加入、不绕过限制、不读取评论、不识别分享链接、不回填完整历史，不自动重处理已经登记的消息编辑。监听账号和 Bot 各用一份 Session；任何手动任务失败都不会借用个人账号。

## 终端登录、检查和停用

以下命令仅在部署了 v1.4.9 代码及相应离线工具后可用。使用自己的 Linux SSH 交互终端：

```bash
tg2cloud listen login --edition clouddrive2
tg2cloud listen status --edition clouddrive2
tg2cloud listen disable --edition clouddrive2
```

OpenList 将 `clouddrive2` 换成 `openlist`。自定义实例加 `--install-dir /自己的已核验安装目录`，不能指向另一 Edition。主机入口核验平台、本机 Docker daemon、容器归属和已有数据挂载，再在该 Bot 容器中执行授权，不重启 Bot 或网关。

源码入口为：

```bash
python3 -B scripts/run_source.py listen --help
```

帮助只用标准库。实际登录需要已运行且含本功能代码的容器。手机号、验证码、两步验证密码只在当前终端隐藏输入，不能发给 Bot，不能作为命令行参数。登录结果必须是原个人账号；拒绝 Bot Token 和切换到另一个账号。成功后仍是停用状态，在 Bot 中明确启用。

Session 位于现有实例 `data/listener/personal.session`，不替换 `data/bot.session`。目录须归容器用户 UID 10001、权限 700，Session 为 600；单独文件锁防止两个进程同时写入。重新登录先停用组件并等待释放锁，保留来源和任务。不要将 Session 当日志上传。

## 在 Bot 中添加来源

1. 管理员私聊 Bot，点击“监听管理”或发送 `/listen`。
2. 确认账号已登录，点击“启用监听账号”，等待连接；失效时按终端登录步骤重新授权。
3. 点击“添加来源”，输入已加入来源的 `@用户名`、稳定聊天 ID 或链接。私有邀请只核验已加入状态，不自动加入。核验访问与内容保护后登记为暂停来源，默认“仅视频、确认后转存”。
4. 打开来源详情，设置筛选规则、命名方案、目录与自动／确认模式；点击“测试规则”只读预览最近最多 10 条，不创建任务、不改游标、不预留额度。
5. 点击“启用”。首次及重新启用均从当前时点开始；暂停期间的历史不自动补抓。账号启用与来源启用是两项独立开关。

添加来源、修改规则期间发送附件，仍按原转存入口处理，不会被设置交互吞掉。文本设置按用户隔离、5 分钟超时，可 `/cancelinput` 取消；按钮一次性使用且 5 分钟失效，重启后须重新打开。

来源详情显示收到、附件、匹配、跳过、待确认、入队与分原因统计。删除来源需要二次确认，停止新接收并忽略其尚未提交计划，保留来源身份历史、已入队任务和云端文件；重新添加同一来源复用历史身份，新计划从当前时点开始。

## 筛选规则

“筛选规则”输入有界 JSON，最多 8192 字符、8 个 OR 组、每类列表最多 20 项；不执行 Shell、任意正则或代码。

```json
{
  "groups": [
    {"types": ["视频"], "extensions": [".MP4", "mkv"], "keywords": ["物理", "数学"], "keyword_mode": "any"}
  ],
  "exclude": ["广告", "试看"],
  "max_bytes": 2147483648,
  "scope": "both"
}
```

表示：视频 AND（MP4 OR MKV）AND（物理 OR 数学），排除广告／试看，最大 2 GiB。`min_bytes`、`max_bytes` 为字节，0 不限制；拿不到可靠大小不入队。类型支持视频、图片、音频、文档、压缩包、其他文件，结合 MIME／媒体属性判断，不把所有 document 都当文档。

- `scope`：`name` 原始文件名、`caption` 实际说明、`both` 两者，默认 both。
- `keywords`：默认任一命中；`keyword_mode: "all"` 全部命中。
- `names`：原始文件名条件；`name_mode` 支持 `exact`、`contains`、`glob`，通配符只允许 `*`、`?`。
- `extensions`：忽略大小写与前导点；`tar.gz` 按完整原始文件名后缀匹配，普通扩展名也可按 Telegram 扩展名匹配。
- 文本按 Unicode NFKC＋casefold 比较，但不更改最终展示文本。
- 不同条件组 AND，组内候选 OR，完整组之间 OR；全局排除、大小、权限、保护和资源限制始终不能绕过。

视频物理 OR PDF 讲义：

```json
{"groups":[{"types":["视频"],"keywords":["物理"]},{"extensions":["pdf"],"keywords":["讲义"]}],"exclude":["广告"],"max_bytes":2147483648}
```

没有包含条件时默认拒绝。确实需要全部附件，必须明确填写 `{"all_attachments":true}`；无效规则不会退回全部匹配。筛选在下载前使用原始事实，人工改名不改变原来的匹配判断。

## 命名与目录

手动转存在“转存设置”或 `/transfer` 设置个人模式；来源使用自己的“命名方案”，不改全局命名。

- `compatible` 默认：保留现有有效原名优先，数字／随机／污染名称继续用已有说明识别和安全兜底。
- `caption`：说明优先；保留成员原有集数／章节，冲突时保留兼容命名，不猜顺序。
- `template`：按显式字段组合。支持 `title`、`season`、`episode`、`chapter`、`year`、`resolution`、`language`、`version`；缺项省略，不生成不存在的信息。分辨率等只按实现中明确识别的标记提取，不做 AI 或 OCR。

```json
{"mode":"template","template":"{title} {episode}","prefixes":["本期推荐"],"suffixes":[],"label":"标题："}
```

`城市漫游 第2季 第03集` 可生成 `城市漫游 S02E03.mp4`。不覆盖同组课程每个成员自己的讲次；公共说明只从同一已获取媒体组安全复用，成员逐个筛选，最多额外读取 10 个同页边界成员，不下载缩略图。极晚到达或独立转发失去说明的成员仍可能回退旧命名。

管理员在转存设置的“目录别名管理”输入：

```json
{"alias":"光学课程","path":"课程/光学","owners":[123456789]}
```

示例 ID 替换成自己已经授权的家庭成员 ID；空 owners 表示只给管理员。`path` 是 Bot 已有上传根目录以内的相对子目录，不是 VPS 路径，不接受绝对路径、`..`、反斜杠或百分号编码。没有授权的目录不会展示给普通用户。

优先级：本次人工选择 > 来源目录别名 > 命名方案目录 > 现有分类 > 默认目录。选择结果替换分类子目录，不重复拼接；接收时保存最终目录、分类、命名和规则版本快照，审批及重试不随设置变化而换目录。Bot 基目录改变时停止原计划，不自动迁移。

## 审批、批次和修正反馈

手动默认仍自动入队；开启确认模式后，发送附件先收到待确认卡片。监听每个来源独立选择自动或确认后转存。`/pending` 按本人分页，每页 10 项，每人最多 200 项，7 天过期；确认前不下载、不预留额度。

卡片可确认、仅本次改名、选择授权目录、忽略；进入正式队列后冻结。媒体扩展名沿用原结果，危险路径字符被拒绝／清理。批次最多 20 项，可确认、改共同主题、改目录，保留各成员集数、章节和扩展名；逐项核验版本与额度，部分失败仍保留对应待确认记录，务必核对结果。

人工修正仅在本人记录保存，最多 2000 条、30 天，不自动训练模型或污染全局规则。明确、可验证的固定前缀修正，管理员可在“修正记录”点击“确认保存前缀规则”，只影响该来源未来计划。其他修改仅留本次记录。来源“命名规则历史与撤销”保留最近 20 次完整配置，可恢复；命名方案输入 `{}` 可清除新增前后缀／模板配置。规则保存不回头改任务或云端文件。

## 恢复、限流和容量边界

使用个人客户端有界轮询接收新消息，每轮每来源最多 100 条，媒体组分页最多扩展 10 条；检查周期 5 秒。仅补拉最近 6 小时；超过窗口可能漏档，管理员需自行核对，不承诺完整历史或端到端 exactly-once。实时接收与重启使用同一持久化收件键，未来即使乱序送达，也不以最大 ID 代替逐条登记。

来源接收结果、计划或跳过决定落盘后才推进游标。计划入队和现有配额预留同一事务；重复审批／重复事件不会重复执行。后续重名后缀以任务结果为准，预览不保留远端名称。

待处理队列达到 100 项或接收记录达到 20000 条时延后监听接收，保持游标，不静默丢弃；手动任务在同一现有分页中优先。收件明细通常保留 7 天，仍待确认引用除外；计划终态保留 30 天。账号停用或冷却时，尚未下载的监听任务保留排队，手动任务继续；网络／接收受限时来源冷却至少 60 秒，轮询及下载的 FloodWait 都按 Telegram 指定时间持久化冷却；授权失效停用账号，权限／内容保护问题暂停来源，不刷屏、不借其他身份。普通 Bot 不随监听停用。

已入队任务仍使用原有并发、磁盘预算、配额、取消、验证及 CloudDrive2／OpenList 各自的提交与恢复策略。消息被删除、附件改变、权限撤销或授权失效时停止自动下载重试，管理员核对后手动重试。流式中断重试是重新开始，不是新增字节级续传。

## 升级、备份与回退

已核对原 v1.4.8 正式提交并补充可信升级载荷基线，不仅凭版本文本接受未知代码。本次更新从业务 schema 2 事务迁移至 **schema 3**，增加读取身份、来源、计划与反馈，不删除旧任务；历史任务默认 `bot` 身份，原名称和目录保持不变。无新增必填环境变量、Bot 运行依赖或 Compose 服务。

升级前按[备份指南](../operations/backup.md)保存匹配的程序／镜像、配置和 `data/tg115.db` 一致性快照。个人 Session 是额外敏感文件：停用监听、等待释放后再备份 `data/listener/personal.session`；离线实例快照包会将存在的该 Session 纳入完整性清单，拒绝活跃 SQLite 旁文件。现有升级不删除监听目录，原数据库备份包含新增表；数据库快照不等于已备份 Session。

回退必须还原旧程序和匹配的升级前数据库快照，不让旧代码打开 schema 3，不删表降级；先停用监听及 Bot，避免两套实例同时处理任务。不要覆盖尚未验证的可用数据。实际生产恢复和真实授权未在本轮执行。
