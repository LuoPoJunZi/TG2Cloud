# 第一次文件转存

## 待发布：可选分类

本地增强尚未发布，不属于正式v1.4.2。以后升级后用`tg2cloud` → 14 → 1选择“不分类、类型、年份、年月、类型/年月”，默认关闭。类型含视频、图片、音频、文档、压缩包、其他文件，优先Telegram媒体类型/MIME、扩展名兜底，不改智能命名和冲突处理。

例如`视频/2026/10/原名.mp4`相对原Bot保存目录。按接收时间及配置时区固定日期，媒体组共用规则/日期，混合媒体可分类型目录。旧任务重试/重启沿用原目录，不移动历史文件。创建目录失败不回退到根目录；基础目录变化须人工核对。CloudDrive2临时校验改名、OpenList预留正式路径直接写入的策略不变。

先用小文件验证整条链路，再提交大量文件。以下操作在你与 Bot 的一对一私聊中完成。

## 发送一个小文件

选择一个自己有权保存的 5～20MB 文件，直接发送或转发给自己的 Bot。Bot 应回复任务编号并把任务写入队列。

群组、频道中的消息不会直接创建任务。当前也没有“自动扫描频道历史”的入口。

## 视频名称优化（v1.2.1）

待发布工具 `tg2cloud naming-preview` 可在本机模拟单媒体说明与原名的选择，显示最终名称和原因；不下载、上传、查询远端重名或修改历史任务。预览与 Bot 共用原规则，不新增 Telegram 命令，也不能模拟未提供的隐藏实体、评论或媒体组。当前线上 v1.4.2 尚无该工具，已审阅源码的样例用法见[维护增强说明](https://github.com/LuoPoJunZi/TG2Cloud/blob/main/docs/development/MAINTENANCE-IMPROVEMENTS.md)。

v1.3.0 起，宣传式原名可用有效说明替换，优先明确标题、长描述和 Telegram 引用块，媒体组选择更完整的说明。以下保留 v1.2.1 的基础规则；v1.3.3 增强单列于后，不会批量改名旧任务或远端数据。

v1.2.1 会为纯数字、video/VID 默认编号等视频名称尝试提取同条消息说明中的标题。正常原名称保留；网址（包括隐藏链接）、话题标签、用户名、常见广告/引流、密码和大小/清晰度说明不作为标题。集数、年份和版本号可以保留，扩展名仍来自原视频。

它只是本地文本规则，不理解视频画面，也不访问链接或评论区；没有可用标题时保留原名称。接收提示显示选定名称，原名称在任务详情保留；已登记任务和云端旧文件不批量改名。v1.2.0 Release 不包含此能力，已有实例需要升级 Bot。

整组转发图片、视频及说明时，v1.2.1 会共用本组首个可用标题，生成 `标题-视频01.mp4`、`标题-图片01.jpg`，分别编号并保留原名；这时本组的新任务即使原名称有意义也会统一命名。说明只有网址、标签或推广且无法提取标题时，不猜测主题。

如果只转发视频而没有说明，仍保留原名。可以改为转发完整组，或自行添加视频说明/修改名称后发送；单独补发文字不会自动关联。接收会短暂等待同组成员，单个成员约 2 秒后回退到单条规则；严重迟到的说明不会改动已登记任务。不会读取原频道、评论区或拼接其他组的文字。

### 多语言与随机名称增强（v1.3.3）

v1.3.3 补识别 `Ab83Kd91X.mp4` 这类混合随机名，支持中文、日文、韩文、英文、重音及其他 Unicode 文字。候选按明确标题、集数、引用、可读信息量评分，不按语言排序，也不只取首行／最长说明；媒体组用同一评分，继续统一编号。正常有意义的单视频原名仍优先。

过滤 `.com@`、其他常见顶级域名、推广账号、话题和纯画质行；不会把整段说明直接拼成超长名字。保留年份、集数、版本号及 `Node.js` 等正常技术名称；明确标为标题的 `1984` 可保留，孤立数字则不猜测。最终扩展名来自附件，沿用非法字符替换与长度限制，例如：

| 原名称 | 实际收到的说明 | 预期新名称 |
| --- | --- | --- |
| `89457236812.mp4` | `三体：黑暗森林 第12集` 后附画质、账号、网址 | `三体_黑暗森林 第12集.mp4` |
| `Ab83Kd91X.mp4` | `君の名は。 君の名は` 后附画质和推广 | `君の名は.mp4` |
| `A8k3P91zX7.mp4` | `오늘의 여행` | `오늘의 여행.mp4` |
| `The Last Journey.mp4` | 另一段说明 | 保留原名 |
| `12345.mp4` | 没有说明或只有链接广告 | 保留原名 |

这仍是轻量本地文本规则，不是内容识别。生僻词、纯字母随机名和模糊推广可能无法可靠区分；提取异常回退原安全名称，不阻止任务接收。无新依赖／配置／数据库迁移，不变更下载、上传、冲突处理或 Bot 菜单；PDF、音频和单张图片沿用既有命名。用户已于 2026-10-19 确认 CloudDrive2 正式 v1.3.3 升级后的实际转存验收完成，不代表 OpenList、全部命名情况或后续改动已验收。

### 待发布的命名边界修复

以下增强已随 **v1.3.4** 正式发布，需实际升级 Bot 才会用于新接收的媒体。保留本节旧标题仅为兼容链接，不表示仍待发布：

- 以 `/` 开头的媒体说明不再当成文字命令跳过。识别带表情的“标题：”，区分 `广告狂人`、`密码疑云` 等作品名与真正的推广／凭据字段。
- 同条说明中相邻的作品名和独立集数可合并；标题中的斜杠安全替换，不丢掉前半段。不拼接无关消息、不读取评论。
- 改善紧贴中文的域名和尾部画质标签过滤，标题标签不成为广告绕过通道；不全局删除正常标题里的 `HDR` 等词语。
- 真实视频元数据与明显错误的原名后缀冲突时保守修正，正常 MKV 等视频后缀保留。原名优先、隐藏链接／剧透遮蔽、无说明兜底和冲突保护继续保留。
- `processed_www.example.test@片段_编号.mp4` 等网址污染名可用本条可靠说明替换；无原名或数字／默认名的单图片也可用自身说明，不关联无关消息。
- 同组恰好一图一视频且扩展名不同，可保存为 `城市夜景旅行记录.jpg` 和 `城市夜景旅行记录.MP4`；多成员或无法区分后缀仍保留编号，扩展名大小写按实际附件保留，不覆盖远端文件。

纯字母随机名仍不强猜；没有新增 AI、OCR、外部 API 或依赖。这些新边界尚未完成真实 Telegram／网关验收，也不会改名历史任务或远端文件。

## 查看处理过程

```text
/queue
/status
/task 123
/watch 123
```

`123` 只是编号示例，请替换成 Bot 实际返回的任务编号。`/watch` 会编辑同一条消息展示进度；Bot 重启后需要重新订阅。

## 理解两种传输

普通模式先完整下载到 VPS，再上传 WebDAV。单文件超过本地任务预算时，自动使用 Telegram 到 rclone 的流式管道。

CloudDrive2 用临时文件上传、改名和复验；OpenList v1.0.2 用预留最终路径直接上传并复验。不要用 CloudDrive2 的状态描述推断 OpenList 必须有同样的改名步骤。

## 确认结果

看到“Bot 完成”后，在目标云存储的官方客户端确认文件夹、文件大小，以及文件是否能打开。重要数据可自行做进一步内容校验。

当前主要使用大小校验，不能仅凭相同文件大小证明内容哈希一致。

## 接着做一次小范围测试

分别测试一个普通落盘文件、一个流式文件和一个可丢弃的测试任务取消。测试正常后，再逐步增大文件与任务规模。

重启恢复测试优先在可重复获取的测试文件上做，不要第一次就用唯一副本验证故障恢复。

:::warning 取消会影响文件
`/cancel 编号` 会尝试清理该任务的远端文件，并在确认清理后删除本地副本。确认任务编号后再操作；只想停止新增调度时使用 `/pause`。
:::
