# 第一次文件转存

先用小文件验证整条链路，再提交大量文件。以下操作在你与 Bot 的一对一私聊中完成。

## 发送一个小文件

选择一个自己有权保存的 5～20MB 文件，直接发送或转发给自己的 Bot。Bot 应回复任务编号并把任务写入队列。

群组、频道中的消息不会直接创建任务。当前也没有“自动扫描频道历史”的入口。

## 视频名称优化（v1.2.1）

主分支有尚未发布的增强：宣传式原名可用有效说明替换，优先长描述和 Telegram 引用块，媒体组选择更完整的说明。v1.3.0 正式安装仍使用下述既有规则；新逻辑只影响新收到的文件，不会批量改名旧任务或远端数据。

v1.2.1 会为纯数字、video/VID 默认编号等视频名称尝试提取同条消息说明中的标题。正常原名称保留；网址（包括隐藏链接）、话题标签、用户名、常见广告/引流、密码和大小/清晰度说明不作为标题。集数、年份和版本号可以保留，扩展名仍来自原视频。

它只是本地文本规则，不理解视频画面，也不访问链接或评论区；没有可用标题时保留原名称。接收提示显示选定名称，原名称在任务详情保留；已登记任务和云端旧文件不批量改名。v1.2.0 Release 不包含此能力，已有实例需要升级 Bot。

整组转发图片、视频及说明时，v1.2.1 会共用本组首个可用标题，生成 `标题-视频01.mp4`、`标题-图片01.jpg`，分别编号并保留原名；这时本组的新任务即使原名称有意义也会统一命名。说明只有网址、标签或推广且无法提取标题时，不猜测主题。

如果只转发视频而没有说明，仍保留原名。可以改为转发完整组，或自行添加视频说明/修改名称后发送；单独补发文字不会自动关联。接收会短暂等待同组成员，单个成员约 2 秒后回退到单条规则；严重迟到的说明不会改动已登记任务。不会读取原频道、评论区或拼接其他组的文字。

## 查看处理过程

```text
/queue
/status
/task 123
/watch 123
```

`123` 只是编号示例，请替换成 Bot 实际返回的任务编号。`/watch` 会编辑同一条消息展示进度；Bot 重启后需要重新订阅。

## 理解两种传输

普通模式先完整下载到 VPS，再上传 WebDAV。单文件超过本地任务预算时，自动使用 Telegram 到 rclone 的流式管道。

CloudDrive2 用临时文件上传、改名和复验；OpenList v1.0.2 用预留最终路径直接上传并复验。不要用 CloudDrive2 的状态描述推断 OpenList 必须有同样的改名步骤。

## 确认结果

看到“Bot 完成”后，在目标云存储的官方客户端确认文件夹、文件大小，以及文件是否能打开。重要数据可自行做进一步内容校验。

当前主要使用大小校验，不能仅凭相同文件大小证明内容哈希一致。

## 接着做一次小范围测试

分别测试一个普通落盘文件、一个流式文件和一个可丢弃的测试任务取消。测试正常后，再逐步增大文件与任务规模。

重启恢复测试优先在可重复获取的测试文件上做，不要第一次就用唯一副本验证故障恢复。

:::warning 取消会影响文件
`/cancel 编号` 会尝试清理该任务的远端文件，并在确认清理后删除本地副本。确认任务编号后再操作；只想停止新增调度时使用 `/pause`。
:::
