# 任务状态与完成边界

状态描述的是 Bot 当前所处的处理阶段，不是云盘官方后台的上传入库进度。

## 常见状态

| 阶段 | 如何理解 |
| --- | --- |
| 排队 | 已保存任务，等待调度、资源和目的端条件允许 |
| 下载中 | 普通模式从 Telegram 下载到 VPS |
| 流式传输中 | Telegram 数据进入 rclone/WebDAV 管道 |
| 上传中 | 普通模式把完整本地文件上传到网关 |
| 清理中 | 远端检查已通过，正在完成本地清理流程 |
| Bot 完成 | Bot 负责的传输、大小检查和收尾流程完成 |
| 失败 | 需要看任务详情中的具体原因；普通模式可能保留完整本地文件 |

具体文字会随 Edition 和版本有所不同。进度与速度应结合阶段解释，不能直接看作网盘官方完成百分比。

## “Bot 完成”证明什么

它证明 Bot 按当前后端策略完成了 WebDAV 传输及大小复验。CloudDrive2 路径涉及临时文件改名后复验，OpenList 路径是最终文件名直接写入后复验。

它不证明云存储官方端已经完成最终处理，也不提供内容哈希一致性的保证。

:::info 重要文件怎么确认
在实际云盘官方客户端检查大小和可打开性；需要更高完整性保证时，自行对内容做校验。不要把 WebDAV 接收与云盘官方确认写成同一件事。
:::

## `/status` 应该怎么看

首页第一行显示 TG2Cloud 是否正常运行以及当前实际 Edition。任务区的 `⏳`、`⬇️`、`⬆️`、`❌` 分别代表排队、活动下载、活动上传和失败数量；零值也会显示，历史完成数量不放在首页。

v1.2.1 保持 `❌ 数字` 样式，但仅计入 Bot 容器配置时区本周发生且目前仍失败的任务，每个任务一次。每周一 00:00 切换范围，下一次刷新显示；不是滚动七天。旧失败记录、文件和恢复操作全部保留，可用 `/tasks failed` 查询；重启不重置本周计数。这项变化不包含在旧 v1.2.0 Release。

实时状态区依次显示 Telegram 到 Bot 的下载、Bot/rclone 写入 WebDAV 网关，以及 Bot 运行环境的网卡收发合计速度。Docker 内的网卡采样通常属于 Bot 容器，不能直接当作整个 VPS 的公网速度；上传也不是网关到云存储的速度。流式使用同一个管道写入采样计入两个方向；三个数值不能机械相加，或用合计减下载推算上传。

:::info 上传测速修复（v1.4.3）
v1.4.3 已包含以下改进，需显式升级 Bot：普通上传每 1 秒采样，优先使用当前文件的平滑速度，缺失时采用有效的文件或总体平均速度，只有字节数时由连续样本计算。首页保持简洁三行，上传仅显示图标和速度，不加说明后缀；家人页也不增加单独说明行，但仍只统计本人数据、不提供 VPS 资源按钮。活动传输没有有效采样、超过 5 秒未更新或部分活动速度未知时显示 `--`，真实零速或空闲显示 `0 B/s`。校验、改名和清理不属于字节传输，可能仍计为活动任务但速度为 0。

首页是手动刷新快照，不自动持续更新；点击 `🔄` 或再次发送 `/status`。很短的写入可能在首个采样前结束，并不保证每个任务都能看到正速度。刷新复用尚有效的健康结果，过期仍走原探测和冷却机制。家人的速度只含本人任务；任一方向数据未知时个人 `🌐` 也显示 `--`，不借用管理员或网卡流量填补。
:::

首页的 `📋`、`🖥`、`🔄` 分别打开任务列表、VPS 资源和刷新当前首页。CPU、可用内存、可用磁盘与 TG2Cloud 本地额度属于 VPS 资源，不与 TG2Cloud 首页状态混为一页。

## 暂停后为何还在传

`/pause` 暂停新任务调度，不强行打断已开始的传输。它会跨重启保留，因此重启后仍不放行新任务时，也要检查是否需要 `/resume`。

## 失败文件会不会丢失

v1.2.1 在任务详情记录验证方法与时间：`size` 只代表远端大小已验证，没有内容哈希保证。旧记录显示“尚无验证记录”；清理前远端大小变化会撤销当前标记、保留副本并要求核对。旧 v1.2.0 Release 不包含这些新字段，不改变旧任务编号或 Session。

普通上传失败会尽量保留完整本地文件，便于重试。流式模式不保留完整副本，失败后通常需要从头读取并重传。取消失败则按保守策略保留数据，避免误删。
