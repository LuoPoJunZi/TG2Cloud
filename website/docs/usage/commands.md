# Bot 命令速查

## 家人个人配额（v1.4.3）

v1.4.3 新增 `/quota`，只看自己的今日完成量、未完成预留、剩余额度和任务数，不增加首页按钮，不允许查询其他用户。Bot 和管理工具须同步升级。

以后更新Bot及管理工具，管理员用`tg2cloud` → 10 → 5为已登记家人设置每日GB、最大排队和同时传输数，0不限。不能给陌生ID授权；家人不能修改自己或他人配额，两个Edition独立。

登记与预留同一事务；去重/重试不重复计量，WebDAV大小复验后计为完成，不等于云盘官方最终完成。失败保留预留，取消未完成任务释放。按配置时区日历日统计，跨日保留仍待处理预留。流式占一个个人槽，仍受全局下载/上传和磁盘保护，降低限制不取消运行任务。

所有命令都受允许用户和私聊限制。下面的 `123` 是任务编号示例。

## 家庭共享（v1.3.3）

这是 v1.3.3 功能，v1.3.2 及更旧版本需先升级 Bot 与本地管理工具。安装仍只填写一个 Telegram 管理员 ID，后续在 Linux 的 `tg2cloud` 菜单按名称选择“Bot 用户管理”（正式 v1.4.3 为 10，v1.4.4 菜单为 5），添加家人的 ID 和备注，确认后生效，无需重启。v1.4.4 菜单还直接列出查看、设置和取消成员配额，选成员后不再进入额外功能菜单；新 UI 须升级离线管理工具才生效。管理员不能从家庭成员菜单移除；每个 Edition 的授权独立。

家人各自私聊同一个 Bot，文件保存到相同目录，不创建个人目录。任务列表、搜索、失败数、重试、取消、恢复和通知仅对应本人；家人首页速度也是本人任务的合计。全局暂停／恢复、诊断、远端巡检清理与 VPS 资源仅管理员可用。原生命令菜单可能仍显示管理员命令，但成员调用会被拒绝。

停用／移除只撤销后续操作和通知，不删除历史、Session 或文件，已接收任务仍继续处理。重新授权同一个 ID 后仍能查询自己的记录。授权保存在现有 SQLite 元数据内，随一致性数据库备份保存，不新增任务表迁移。旧 Bot 回退后只认原管理员；不要通过改安装 ID 来迁移管理员身份。

手机看片使用另一套[外部 WebDAV 家庭只读账号](/deploy/external-webdav/)，不会因加入 Bot 自动开通。任务私聊隔离不等于网盘文件隔离：有共同目录读取权限的家人可以看到其中全部文件。最多新增 32 位可信家人，共用已有磁盘预算及调度窗口，不增加个人配额或目录。

## v1.2.1：任务恢复与查询

以下恢复与查询功能适用于 v1.2.1，旧 v1.2.0 EXE 不包含这些改动。

| 命令 | 作用 |
| --- | --- |
| `/restart 123` | 确认后重新转存已取消任务，保留编号与历史；活动任务和已完成任务仍去重 |
| `/recover 123` | 确认后换名重传，保留原远端文件，优先复用完整本地副本 |
| `/search 文件名` | 当前用户的文件名查询，最多显示 5 项；更多结果请缩小范围 |
| `/tasks failed`、`/tasks cancelled` | 失败/取消任务分页，按回复中的最后编号继续查询 |

确认码一次有效、5 分钟到期，重启或任务变化后需重新确认。401/403/429 与远端冲突不再无限自动重试；详见[失败恢复](/troubleshooting/transfer/)。既有菜单布局不变。

## 查询与诊断

| 命令 | 作用 |
| --- | --- |
| `/start` | 打开 TG2Cloud 状态首页和快捷按钮 |
| `/help` | 打开使用帮助 |
| `/queue` | 查看第一页最近任务，每页 5 项 |
| `/queue 2` | 查看第二页 |
| `/status`、`/performance` | TG2Cloud 状态首页、实时速度和任务统计 |
| `/task 123` | 查看某个任务详情 |
| `/watch 123` | 每 5 秒编辑同一消息展示进度，重启后需重新订阅 |
| `/doctor` | 只读诊断，不创建远端测试文件 |
| `/orphans` | 只读巡检疑似遗留的 `.uploading-*` 文件 |

当前 v1.2.1 源码的 OpenList `/doctor` 还显示最近实际探测时间、401/429 分类与剩余冷却。刷新不会绕过退避，主状态首页仍保持简洁；写入能力需要单独 [WebDAV 验收](/deploy/verification/)。

## 调度与重试

| 命令 | 作用与注意 |
| --- | --- |
| `/pause` | 持久暂停新任务调度，不打断当前活动传输 |
| `/resume` | 恢复新任务调度 |
| `/retry 123` | 重试一个失败任务 |
| `/retry all` | 一次重新排队最多 100 个可重试任务 |
| `/stream 123` | 将排队或下载失败任务切为流式模式 |

重试前先修复错误原因。401 未解决就反复 `/retry all`，不会自动修好凭据。

## 取消与清理

| 命令 | 实际影响 |
| --- | --- |
| `/cancel 123` | 清理并复查当前任务远端路径，再清理本地副本 |
| `/orphans clean` | 先获取一次性确认码，再按 Bot 提示显式清理遗留临时文件 |

:::danger 删除操作不是只读
确认清理对象后再执行。取消采用失败关闭策略：如果不能确认远端已经清理，会保留数据，不把失败当作取消成功。
:::

## 输入框左侧的原生命令菜单

当前 Bot 启动时注册 7 个常用命令：`/status`、`/queue`、`/pause`、`/resume`、`/doctor`、`/orphans`、`/help`。

`/start`、`/status` 和 `/performance` 的首页使用三个 Emoji 按钮：`📋` 打开已有任务列表，`🖥` 打开 VPS 资源，`🔄` 原地刷新首页。VPS 资源页使用 `🔄` 刷新资源、使用 `↩️` 返回最新首页；按钮切换只编辑当前消息。带任务编号的命令仍需要手动输入。

菜单注册失败不一定阻止 Bot 启动；可以直接发送文字命令。历史旧按钮消息不代表当前仍有相同界面。

## 不要照搬旧教程

TG115 上游历史中出现的人工确认用法不等于当前日常必需操作。TG2Cloud 日常统一以“Bot 完成”展示，不要求逐条人工执行确认命令。完成语义见 [任务状态](/usage/status/)。
