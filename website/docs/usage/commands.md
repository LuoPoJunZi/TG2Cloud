# Bot 命令速查

所有命令都受允许用户和私聊限制。下面的 `123` 是任务编号示例。

## 查询与诊断

| 命令 | 作用 |
| --- | --- |
| `/start`、`/help` | 打开使用帮助 |
| `/queue` | 查看第一页最近任务，每页 5 项 |
| `/queue 2` | 查看第二页 |
| `/status`、`/performance` | 同一份系统状态、阶段速度和任务统计 |
| `/task 123` | 查看某个任务详情 |
| `/watch 123` | 每 5 秒编辑同一消息展示进度，重启后需重新订阅 |
| `/doctor` | 只读诊断，不创建远端测试文件 |
| `/orphans` | 只读巡检疑似遗留的 `.uploading-*` 文件 |

## 调度与重试

| 命令 | 作用与注意 |
| --- | --- |
| `/pause` | 持久暂停新任务调度，不打断当前活动传输 |
| `/resume` | 恢复新任务调度 |
| `/retry 123` | 重试一个失败任务 |
| `/retry all` | 一次重新排队最多 100 个可重试任务 |
| `/stream 123` | 将排队或下载失败任务切为流式模式 |

重试前先修复错误原因。401 未解决就反复 `/retry all`，不会自动修好凭据。

## 取消与清理

| 命令 | 实际影响 |
| --- | --- |
| `/cancel 123` | 清理并复查当前任务远端路径，再清理本地副本 |
| `/orphans clean` | 先获取一次性确认码，再按 Bot 提示显式清理遗留临时文件 |

:::danger 删除操作不是只读
确认清理对象后再执行。取消采用失败关闭策略：如果不能确认远端已经清理，会保留数据，不把失败当作取消成功。
:::

## 输入框左侧的原生命令菜单

当前 Bot 启动时注册 7 个常用命令：`/status`、`/queue`、`/pause`、`/resume`、`/doctor`、`/orphans`、`/help`。

新回复主要使用文字，不在每条消息下附加旧版快捷按钮。带任务编号的命令仍需要手动输入。

菜单注册失败不一定阻止 Bot 启动；可以直接发送文字命令。历史旧按钮消息不代表当前仍有相同界面。

## 不要照搬旧教程

TG115 上游历史中出现的人工确认用法不等于当前日常必需操作。TG2Cloud 日常统一以“Bot 完成”展示，不要求逐条人工执行确认命令。完成语义见 [任务状态](/usage/status/)。
